# 手眼标定功能测试与验证

本文给出 eye-in-hand 手眼标定从环境检查、AprilGrid 位姿发布验证、Web 四步向导操作（启动 → 采集+手动位姿 → 一键求解 → 应用结果）、TF 闭环复验的完整步骤。除特别说明外，命令均在工作区根目录 `/home/ubuntu/ros2_ws` 执行，示例相机命名空间为 `/my_camera`。

手眼标定使用 **AprilGrid 标定板**（`tag36h11`，4×3 共 12 个标签），通过 Web Dashboard 录入手动位姿采集样本，求解 AX=XB 得到相机到末端（`camera_to_gripper`）的齐次变换，并通过静态 TF 发布器加载。机器人在本项目中暂不涉及，标定时手动输入位姿即可。

## 1. 验收范围与通过条件

数据链路如下：

```text
Web Dashboard 手眼标定向导
  -> 手动输入机械臂位姿 (x/y/z mm, roll/pitch/yaw °)
  + AprilGrid 板卡位姿 (/apriltag/transform, TransformStamped)
    -> /api/handeye/samples (采集 ≥4 组，建议 10-20 组)
    -> /api/handeye/start (后台线程 solve_hand_eye)
    -> camera_to_gripper 4x4 齐次矩阵 + 闭环误差
    -> handeye_calibration.yaml
    -> /api/handeye/apply 写入 + ReloadCalibration 热重载
    -> handeye_static_tf_broadcaster 发布 /tf_static
    -> tool0 -> my_camera_optical_frame
```

完整功能通过必须同时满足：

1. 相机持续发布原始图像，AprilTag 检测器发布 `/apriltag/transform` 话题；
2. Web Dashboard 可访问，手眼标定页面显示"标签位姿就绪"；
3. 采集阶段成功收集至少 4 组满足运动多样性阈值的样本（生产建议 10-20 组）；
4. 求解阶段成功完成，`phase: done`；
5. 闭环误差在可接受阈值内，示例使用平移 `1.0 mm`、旋转 `0.5°`；
6. 输出 YAML 包含有效的 4x4 `camera_to_gripper_matrix` 和 `gripper_to_camera_matrix`，且为有限数值；
7. 点击"应用结果"后，YAML 写入 `handeye_calibration_file` 路径，静态 TF 发布器发布 `tool0 -> my_camera_optical_frame` 变换；
8. `tf2_echo` 能解析从 `tool0` 到相机光学坐标系的变换，平移量级与标定结果一致。

求解成功只表示数学过程完成，不代表采样覆盖充分。生产验收还应结合闭环误差、样本数量和 TF 实测共同判断。

## 2. 测试准备

### 步骤 1：加载环境并确认软件包

**指令：**

```bash
cd /home/ubuntu/ros2_ws
source /opt/ros/humble/setup.bash
source install/setup.bash

ros2 pkg prefix handeye_calibration
ros2 pkg prefix apriltag_pose_reader_interfaces
python3 -c "import cv2, numpy; print('handeye dependencies: OK')"
```

**通过结果：**

- 两个 `ros2 pkg prefix` 命令输出安装路径；
- Python 输出 `handeye dependencies: OK`。

**失败说明：**

- `Package not found`：先执行构建，再重新加载环境。

构建命令：

```bash
colcon build --symlink-install --packages-up-to industrial_vision_bringup
source install/setup.bash
```

### 步骤 2：核对实体 AprilGrid

手眼标定使用与内参标定相同的 AprilGrid 板卡：

| 项目 | 示例值 | 要求 |
| --- | --- | --- |
| 标签族 | `tag36h11` | 必须一致 |
| 行数 | `4` | 必须为 4 |
| 列数 | `3` | 必须为 3 |
| 标签 ID | `0` 至 `11` | 共 12 个 |
| 单标签黑色外框边长 | `0.05 m` | 必须实测后填写 |
| 相邻标签黑色外框间距 | `0.01 m` | 必须实测后填写 |

**检查方法：** 用直尺或卡尺测量打印后的实际尺寸，不使用设计文件标称尺寸代替实测值。板卡必须平整，不能折弯。

**说明：** `tag_size_m` 或 `tag_spacing_m` 与实际板卡不符会使 AprilGrid 位姿估计建立在错误的三维点坐标上，直接导致手眼变换求解错误。内参标定和手眼标定必须使用同一块 AprilGrid 板卡。

### 步骤 3：启动相机流水线并启用 AprilTag 检测

**终端 A 指令：**

```bash
cd /home/ubuntu/ros2_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 launch industrial_vision_bringup vision_pipeline.launch.py \
  camera_id:=my_camera \
  camera_config:="$PWD/deploy/basler_camera/config/aca2500_106611_18.yaml" \
  enable_apriltag:=true \
  enable_keyence:=false \
  handeye_calibration_file:=$PWD/handeye_calibration.yaml
```

**通过结果：** 相机节点、AprilTag 检测器、Web Dashboard 和静态 TF 广播器启动，无设备占用、配置读取或组件加载错误。

**说明：** `handeye_calibration_file` 参数指定手眼标定结果的输出路径，"应用结果"时 YAML 会写入此路径。`enable_apriltag:=true` 是必需的，手眼标定需要 AprilTag 检测器运行以发布板卡位姿变换。

### 步骤 4：验证 AprilGrid 位姿发布

**终端 B 指令：**

```bash
source /opt/ros/humble/setup.bash
source /home/ubuntu/ros2_ws/install/setup.bash

# 确认图像发布
timeout 10 ros2 topic hz /my_camera/pylon_ros2_camera_node/image_raw

# 确认 AprilTag 变换话题存在且有数据
ros2 topic info /apriltag/transform --verbose
timeout 10 ros2 topic echo /apriltag/transform --once
```

**通过结果：**

- `image_raw` 10 秒内能统计到稳定频率；
- `/apriltag/transform` 话题存在，`Publisher count` 至少为 1；
- 将 AprilGrid 板卡放在相机视野内时，`ros2 topic echo` 能输出 `TransformStamped` 消息，`child_frame_id` 为 `apriltag_board`（或具体标签 frame）。

**失败说明：**

- 无变换发布：检查板卡是否在视野内、曝光和对焦是否合适、`apriltag_36h11.yaml` 中的 `tag_size_m` 是否与实物一致。

## 3. Web 四步向导标定流程

打开 `http://127.0.0.1:8080`，进入"手眼标定"页面。整个标定过程在浏览器中完成，无需打开新的终端或手动启动 Action server。

### 步骤 5：启动手眼标定

**操作：** 点击页面上的"启动标定"按钮。

**HTTP 等价：**

```bash
curl -X POST http://127.0.0.1:8080/api/handeye/session
```

**通过结果：**

- 页面状态变为"采集会话已创建"；
- 步骤条进入第二步"采集样本"；
- 会话 ID 显示在页面上。

### 步骤 6：采集样本（重复至少 4 次，建议 10-20 次）

**操作：**

1. 将 AprilGrid 板卡放在相机视野内，确认页面左侧实时画面显示板卡，且"标签位姿"状态为"就绪"；
2. 在位姿表单中输入当前机械臂位姿：
   - X / Y / Z（单位 mm）
   - Roll / Pitch / Yaw（单位 °）
3. 点击"采集样本"按钮。

Dashboard 自动抓取当前画面（带 AprilTag 检测叠加），并记录对应的 AprilTag 变换矩阵和手动输入的位姿，作为一个样本对保存。

**HTTP 等价：**

```bash
# 查看当前预览（带 AprilTag 检测叠加）
curl --fail --output /tmp/handeye_preview.jpg \
  http://127.0.0.1:8080/api/handeye/preview

# 采集一组样本
curl -X POST http://127.0.0.1:8080/api/handeye/samples \
  -H 'Content-Type: application/json' \
  -d '{"x_mm": 300, "y_mm": 0, "z_mm": 400, "roll_deg": 0, "pitch_deg": 0, "yaw_deg": 0}'
```

**单次采集通过结果示例：**

```json
{
  "id": "sample_001.jpg",
  "filename": "sample_001.jpg",
  "created_at": "2026-09-03T12:00:00Z",
  "robot_pose": {"x_mm": 300, "y_mm": 0, "z_mm": 400, "roll_deg": 0, "pitch_deg": 0, "yaw_deg": 0},
  "tag_detections": 12,
  "last_robot_translation_mm": 0.0,
  "last_robot_rotation_deg": 0.0
}
```

**必须覆盖：**

1. 每次输入不同的位姿值，覆盖工作空间不同区域；
2. 位姿有不同姿态（绕 X、Y、Z 轴分别旋转）；
3. 每次输入的平移变化 >= 1mm、旋转变化 >= 1°，否则 Dashboard 会拒绝采集并提示"与上一个样本位姿过于接近"；
4. AprilGrid 板卡固定不动，始终在相机视野内且清晰可辨；
5. 页面右侧"姿态多样性"指示器显示平移跨度和旋转跨度逐步增长。

**采集后查询状态：**

```bash
curl --fail http://127.0.0.1:8080/api/handeye | python3 -m json.tool
```

**通过结果：** `samples` 数组中有 4 至 20 条记录；`diversity` 中 `translation_span_mm` 和 `rotation_span_deg` 不应全部接近 0。

### 步骤 7：一键求解

**操作：** 采集完成后点击"一键求解"按钮。页面会弹出参数确认，可选择求解算法和闭环误差阈值，确认后提交。

**HTTP 等价：**

```bash
curl -X POST http://127.0.0.1:8080/api/handeye/start \
  -H 'Content-Type: application/json' \
  -d '{
    "algorithm": "tsai",
    "base_frame": "base_link",
    "gripper_frame": "tool0",
    "camera_frame": "camera_optical_frame",
    "target_frame": "apriltag_board",
    "max_closed_loop_translation_m": 0.001,
    "max_closed_loop_rotation_deg": 0.5
  }'
```

**通过结果：**

- 页面状态变为"正在求解"；
- 求解完成后显示：
  - `phase: done`；
  - 闭环平均/最大平移误差和旋转误差；
  - `camera_to_gripper` 平移向量；
  - `gripper_to_camera` 4x4 矩阵；
  - 算法名称和样本数。

**失败说明：**

- `至少需要 4 组姿态样本` → 回去补采集；
- `Robot poses have insufficient rotational diversity` → 增加绕不同轴的旋转样本；
- `闭环平移误差 ... 超过阈值` → 增加样本数量、改善板卡可见性、扩大运动范围后重新标定；
- `与上一个样本位姿过于接近` → 输入差异更大的位姿值。

### 步骤 8：应用结果

**操作：** 求解成功后，页面显示"应用结果"按钮。点击后 Dashboard 将结果 YAML 复制到 `handeye_calibration_file` 指定路径，并调用静态 TF 广播器的 `ReloadCalibration` 服务热重载变换。

**HTTP 等价：**

```bash
# 先查当前可用的结果
curl http://127.0.0.1:8080/api/handeye | python3 -m json.tool
# 取 result.id 字段
curl -X POST http://127.0.0.1:8080/api/handeye/apply \
  -H 'Content-Type: application/json' \
  -d '{"id": "20260903T120000-ab12cd"}'
```

**通过结果：**

- 返回 `{"success": true, "target_path": "..."}`；
- 返回的 `target_path` 与流水线启动时 `handeye_calibration_file` 参数一致；
- 静态 TF 广播器自动重载变换，无需重启流水线。

**失败说明：**

- `未配置 handeye_calibration_file 参数` → 启动流水线时未传入 `handeye_calibration_file` 参数；
- `TF 广播器重载失败` → 检查静态 TF 广播器是否已启动（`handeye_calibration_file` 参数非空时流水线会自动启动它）。

## 4. 闭环复验

### 步骤 9：验证 TF 变换

**终端 B 指令：**

```bash
# 验证 tool0 到相机光学坐标系的变换
ros2 run tf2_ros tf2_echo tool0 my_camera_optical_frame

# 验证静态 TF 话题
ros2 topic echo /tf_static --once | grep -A10 my_camera_optical_frame
```

**通过结果：**

- `tf2_echo` 输出有效的 `Translation` 和 `Rotation`，平移量级与手眼标定结果一致（通常在厘米级）；
- 四元数已归一化，`norm` 接近 1；
- `/tf_static` 中包含 `tool0 -> my_camera_optical_frame` 的静态变换。

**失败说明：**

- `LookupException` → 静态 TF 未发布，检查 `handeye_calibration_file` 参数是否正确传入、YAML 路径是否有效；
- 变换值异常 → 检查 YAML 中的矩阵是否为有限数值、手眼标定是否真正成功。

### 步骤 10：热重载标定（无需重启）

如需更新手眼结果而不重启流水线，可调用静态发布器的 `reload_calibration` 服务：

```bash
ros2 service call \
  /my_camera/handeye_static_tf_broadcaster/reload_calibration \
  apriltag_pose_reader_interfaces/srv/ReloadCalibration \
  "{calibration_file: '/home/ubuntu/ros2_ws/handeye_calibration.yaml'}"
```

**通过结果：**

- 返回 `success: true`，`message` 包含 `Reloaded calibration from ...`；
- 重新调用 `tf2_echo` 验证变换已更新。

### 步骤 11：完整 TF 链路验证

**终端 B 指令：**

```bash
# 从 base_link 到相机光学坐标系
ros2 run tf2_ros tf2_echo base_link my_camera_optical_frame

# 当 AprilGrid 在视野内时，从 tool0 到 AprilGrid 板卡
ros2 run tf2_ros tf2_echo tool0 apriltag_board

# 列出所有活动 frame
ros2 run tf2_tools view_frames
```

**通过结果：**

- `base_link -> my_camera_optical_frame` 变换有效，经过 `tool0` 中转；
- 当 AprilGrid 在视野内时，`tool0 -> apriltag_board` 变换有效；
- `view_frames` 生成的 TF 树包含 `base_link -> tool0 -> my_camera_optical_frame -> apriltag_board` 链路。

至此，Web 向导采集、求解、YAML 输出、静态 TF 加载和 TF 闭环验证全部通过，才判定手眼标定功能闭环验证成功。

## 5. 离线求解（可选路径）

如需对 Web 会话导出的 CSV 重新求解，可使用离线 CLI：

```bash
ros2 run handeye_calibration handeye_calibrate \
  --input poses.csv \
  --output handeye_calibration.yaml \
  --algorithm tsai \
  --base-frame base_link \
  --gripper-frame tool0 \
  --camera-frame my_camera_optical_frame \
  --target-frame apriltag_board
```

CSV 格式包含 `gripper2base_r`、`gripper2base_t`、`target2cam_r`、`target2cam_t` 四列（旋转为 9 元素 3x3 矩阵行优先，平移为 3 元素向量）。具体参数以 `--help` 输出为准。

## 6. 常见失败与定位

| 现象或结果 | 含义 | 处理方法 |
| --- | --- | --- |
| 点击"启动标定"无反应 | Dashboard 后端异常 | 检查容器日志、`/api/handeye` 是否返回正常 |
| "标签位姿未就绪" | 未接收到 AprilTag 变换 | 检查板卡是否在视野内、`enable_apriltag:=true`、`apriltag_36h11.yaml` 配置 |
| "实时画面尚未就绪" | 相机图像未发布 | 先打开实时流，检查相机连接和图像话题 |
| "机械臂位姿格式错误" | 输入值非数字或缺失 | 确保所有 6 个位姿字段都已填写有效数字 |
| "与上一个样本位姿过于接近" | 运动多样性不足 | 输入差异更大的位姿值（平移 >= 1mm、旋转 >= 1°） |
| `至少需要 4 组姿态样本` | 有效样本不足 4 组 | 继续采集更多样本 |
| `insufficient rotational diversity` | 旋转运动多样性不足 | 增加绕不同轴的旋转样本 |
| `insufficient overall rotational span` | 旋转跨度不足 | 扩大旋转范围（建议跨度 >= 15°） |
| 闭环平移误差超阈值 | 采样覆盖不足或位姿估计噪声大 | 增加样本数量、改善光照和对焦、扩大运动范围 |
| 闭环旋转误差超阈值 | 旋转运动多样性不足 | 增加绕不同轴的旋转样本 |
| `未配置 handeye_calibration_file` | 启动参数缺失 | 启动流水线时传入 `handeye_calibration_file` 路径 |
| `TF 广播器重载失败` | 静态 TF 广播器未运行 | 检查 `handeye_calibration_file` 参数非空时是否自动启动了广播器 |
| `tf2_echo` 报 LookupException | TF 树断裂 | 逐级检查 `base_link -> tool0 -> my_camera_optical_frame` |
| YAML 矩阵含 NaN 或 Inf | 数值溢出 | 检查输入位姿是否合理 |
