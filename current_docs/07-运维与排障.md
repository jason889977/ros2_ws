# 运维与排障

## 1. 启动验收顺序

按依赖顺序检查，避免只凭节点名称判断系统可用。

### 1.1 容器状态

```bash
docker inspect --format \
  '{{.State.Status}} {{if .State.Health}}{{.State.Health.Status}}{{end}}' \
  basler_camera
docker logs --tail 200 basler_camera
```

### 1.2 手动健康检查

```bash
docker exec basler_camera \
  /opt/ros2_ws/deploy/basler_camera/healthcheck.sh
```

### 1.3 ROS 图

```bash
docker exec basler_camera bash -lc '
  source /opt/ros/humble/setup.bash
  source /opt/ros2_ws/install/setup.bash
  ros2 node list
  ros2 topic list -t
'
```

### 1.4 实际数据

```bash
docker exec basler_camera bash -lc '
  source /opt/ros/humble/setup.bash
  source /opt/ros2_ws/install/setup.bash
  timeout 10 ros2 topic echo \
    /my_camera/pylon_ros2_camera_node/camera_info --once
  timeout 10 ros2 topic echo /my_camera/vision/status --once
'
```

## 2. 健康等级解释

容器健康检查失败的直接条件：

- 收不到 `camera_info`；
- 任一已启用模块节点不存在；
- 收不到 `vision/status`；
- 汇总等级为 ERROR 或 STALE。

WARN 不会直接令容器 unhealthy，但仍应检查 `summary`、`component_names` 和 `component_messages`。

## 3. 相机无图像或启动超时

检查顺序：

1. 相机供电、网线和交换机链路；
2. 宿主机网卡地址是否与相机同网段；
3. 相机是否被另一个进程独占；
4. `CAMERA_CONFIG_FILE` 是否存在且匹配实体设备；
5. 网卡、交换机、相机和 `CAMERA_MTU_SIZE` 是否一致；
6. pylon SDK 是否能发现设备；
7. 驱动诊断与容器日志。

```bash
ip address
ip link show
ping -c 3 <camera-ip>
docker logs --tail 300 basler_camera | \
  grep -Ei 'pylon|camera|timeout|error|exception'
```

不要仅检查话题是否注册；必须实际接收一条 `camera_info` 和图像消息。

## 4. AprilTag 无输出

```bash
ros2 node list | grep -E 'apriltag|apriltag_pose_reader'
ros2 topic echo /my_camera/detections --once
ros2 topic echo /my_camera/apriltag/transform --once
ros2 topic echo /my_camera/diagnostics --once
ros2 run tf2_ros tf2_echo \
  basler_aca2500_106611_18 my_camera/tag36h11:0
```

重点检查：

- `ENABLE_APRILTAG=true`；
- 标签族、ID、边长和 frame 前缀；
- 相机 `camera_info_url` 是否成功加载；没有有效标定时 Basler 组件不会发布 `image_rect`；
- `image_rect` 是否实际有消息；
- 标签是否在视野内、曝光是否合适；
- `camera_frame` 是否与图像/TF 使用的 frame 一致。

没有可见标签时无位姿输出是正常行为。

## 5. Keyence 扫码器离线

```bash
ping -c 3 <scanner-ip>
ros2 service call /my_camera/scanner/trigger \
  std_srvs/srv/Trigger '{}'
ros2 topic echo /my_camera/diagnostics --once
```

检查：

- `SCANNER_IP` 与 `SCANNER_PORT`；
- 扫码器 TCP 服务是否开启；
- 防火墙和路由；
- `RECONNECT_INTERVAL_S` 是否为 0。设为 0 时不会创建周期重连定时器，但手动触发仍会尝试连接。

超时或连接错误后节点会断开当前 socket，后续由重连定时器恢复。

## 6. Dashboard 不可访问

```bash
curl -v http://127.0.0.1:8080/health
ros2 node list | grep web_dashboard
ss -lntp | grep ':8080'
```

当前 Dashboard 仅监听 `127.0.0.1`。从其他机器直接访问工控机 IP 不会成功，这是监听边界，不是 ROS 故障。

若本机 `/health` 正常但页面无数据，继续检查：

- `/my_camera/vision/status`；
- `/my_camera/diagnostics`；
- 浏览器 WebSocket `/ws`；
- `camera_id` 配置。

## 7. 事件日志和磁盘

宿主机默认目录：

```text
deploy/basler_camera/data/events/
deploy/basler_camera/data/archive/
deploy/basler_camera/data/calibration/
```

检查：

```bash
du -sh deploy/basler_camera/data/events \
  deploy/basler_camera/data/archive \
  deploy/basler_camera/data/calibration
df -h
find deploy/basler_camera/data/events -maxdepth 1 -type f -ls
find deploy/basler_camera/data/calibration -maxdepth 2 -type f -ls
```

事件日志自身按大小轮转；Docker stdout/stderr 由 Compose 的 `json-file` 驱动独立轮转。标定目录保留采集图、结果 YAML、去畸变预览和历史记录，需要按现场保留策略定期归档或清理。三者不是同一套日志。

## 8. ROS 2 发现异常

容器使用 host 网络。宿主机调试终端需匹配：

```bash
export ROS_DOMAIN_ID=0
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
source /opt/ros/humble/setup.bash
source /home/ubuntu/ros2_ws/install/setup.bash
ros2 node list
```

如果容器内可见、宿主机不可见，检查环境变量、DDS 配置、防火墙和多网卡路由。

## 9. 收集故障信息

```bash
mkdir -p /tmp/vision_support
docker inspect basler_camera \
  > /tmp/vision_support/container-inspect.json
docker logs --timestamps basler_camera \
  > /tmp/vision_support/container.log 2>&1
docker exec basler_camera bash -lc '
  source /opt/ros/humble/setup.bash
  source /opt/ros2_ws/install/setup.bash
  ros2 node list
  ros2 topic list -t
  ros2 service list -t
' > /tmp/vision_support/ros-graph.txt 2>&1
```

对外发送前删除设备序列号、现场 IP、环境变量秘密和业务扫码内容。
