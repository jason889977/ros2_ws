# 相机内参标定功能测试与验证

本文给出 AprilGrid 相机内参标定从环境检查、Web 四步向导操作、标定结果验证到相机加载复验的完整步骤。除特别说明外，命令均在工作区根目录 `/home/ubuntu/ros2_ws` 执行，示例相机命名空间为 `/my_camera`。

## 1. 验收范围与通过条件

数据链路如下：

```text
Basler 原始图像
  -> Web 四步向导（启动 → 引导拍照 → 一键标定 → 应用内参）
  -> /calibrate_camera Action
  -> OpenCV 内参 K、畸变 D、重投影误差 RMS
  -> camera_calibration.yaml
  -> /api/calibration/apply 写入 camera_info_url
  -> camera_info + image_rect
```

完整功能通过必须同时满足：

1. 相机持续发布与标定分辨率一致的原始图像；
2. 至少 3 张图检测到 AprilGrid，建议采集 12 至 20 张且覆盖画面各区域、远近和倾角；
3. 一键标定成功结束，`success: true`，`images_used >= 3`；
4. `reprojection_error` 不超过测试阈值，本文示例使用 `2.0 px`；
5. 输出 YAML 的尺寸、3x3 内参、5 个畸变参数均有效且为有限数值；
6. 点击"应用内参"后，相机发布的 `camera_info` 与新 YAML 一致，并能发布 `image_rect`；
7. 校正图像没有明显新增弯曲、拉伸或黑边异常。

Action 成功只表示求解过程完成，不代表采样覆盖充分。生产验收还应结合 RMS、图像覆盖和校正画面共同判断。

## 2. 测试准备

### 步骤 1：加载环境并确认软件包

**指令：**

```bash
cd /home/ubuntu/ros2_ws
source /opt/ros/humble/setup.bash
source install/setup.bash

ros2 pkg prefix aprilgrid_calibration
ros2 pkg prefix apriltag_pose_reader_interfaces
python3 -c "import cv2, numpy, yaml, apriltag; print('calibration dependencies: OK')"
```

**通过结果：**

- 两个 `ros2 pkg prefix` 命令输出安装路径；
- Python 输出 `calibration dependencies: OK`。

**失败说明：**

- `Package not found`：先执行构建，再重新加载环境；
- `No module named apriltag`：当前 Python 环境缺少 AprilTag 检测库，标定服务无法检测板卡。

构建命令：

```bash
colcon build --symlink-install --packages-up-to industrial_vision_bringup
source install/setup.bash
```

### 步骤 2：核对实体 AprilGrid

本实现当前只接受以下板卡：

| 项目 | 示例值 | 要求 |
| --- | --- | --- |
| 标签族 | `tag36h11` | 必须一致 |
| 行数 | `4` | 必须为 4 |
| 列数 | `3` | 必须为 3 |
| 标签 ID | `0` 至 `11` | 共 12 个 |
| 单标签黑色外框边长 | `0.05 m` | 必须实测后填写 |
| 相邻标签黑色外框间距 | `0.01 m` | 必须实测后填写 |

**检查方法：** 用直尺或卡尺测量打印后的实际尺寸，不使用设计文件标称尺寸代替实测值。

**说明：** `tag_size_m` 或 `tag_spacing_m` 填错会使求解建立在错误的三维点坐标上。板卡必须平整，不能折弯；打印缩放必须保持横纵比例一致。

### 步骤 3：启动真实相机流水线

**终端 A 指令：**

```bash
cd /home/ubuntu/ros2_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 launch industrial_vision_bringup vision_pipeline.launch.py \
  camera_id:=my_camera \
  camera_config:="$PWD/deploy/basler_camera/config/aca2500_106611_18.yaml" \
  enable_apriltag:=false \
  enable_keyence:=false
```

**通过结果：** 相机节点和 Dashboard 启动，无设备占用、配置读取或组件加载错误。

### 步骤 4：确认原始图像分辨率和频率

**终端 B 指令：**

```bash
source /opt/ros/humble/setup.bash
source /home/ubuntu/ros2_ws/install/setup.bash

timeout 10 ros2 topic echo \
  /my_camera/pylon_ros2_camera_node/image_raw --once \
  --field width
timeout 10 ros2 topic echo \
  /my_camera/pylon_ros2_camera_node/image_raw --once \
  --field height
timeout 10 ros2 topic hz \
  /my_camera/pylon_ros2_camera_node/image_raw
```

**通过结果：**

- 宽、高均为大于零的整数；
- 10 秒内能统计到稳定频率；
- 后续所有采集图片保持这个分辨率，不再修改 ROI、binning 或相机输出尺寸。

**失败含义：** 原始图像未发布时不要继续标定。优先检查相机连接、设备占用、IP、序列号、曝光和触发模式。

## 3. Web 四步向导标定流程

打开 `http://127.0.0.1:8080`，进入"相机内参标定"页面。整个标定过程在浏览器中完成，无需打开新的终端或手动管理 Action server。

### 步骤 5：启动标定

**操作：** 点击页面上的"启动标定"按钮。

**HTTP 等价：**

```bash
curl -X POST http://127.0.0.1:8080/api/calibration/service/toggle
curl -X POST http://127.0.0.1:8080/api/calibration/session
```

**通过结果：**

- 页面状态变为"采集中"；
- 标定 Action server 自动启动（无需手动 `ros2 run`）；
- 创建新的采集会话，会话 ID 显示在页面上。

### 步骤 6：引导拍照（重复 12-20 次）

**操作：** 按页面 Pose Guide 提示调整 AprilGrid 板卡姿态，每次调整稳定后点击"采集"按钮。

Pose Guide 会显示 15 个预设姿态（中心、四边、四角、近中远、X/Y 轴倾斜），当前姿态高亮，已完成的打勾。页面右侧实时显示覆盖度热力图，帮助判断是否已充分覆盖画面。

**HTTP 等价：**

```bash
# 查看当前预览（带 AprilGrid 检测叠加）
curl --fail --output /tmp/calib_preview.jpg \
  http://127.0.0.1:8080/api/calibration/preview

# 采集一张
curl --fail -X POST http://127.0.0.1:8080/api/calibration/captures
```

**单次采集通过结果示例：**

```json
{"filename":"calib_001.jpg","detections":12,"coverage":{"x":0.5,"y":0.5,"size":0.2,"skew":0.1}}
```

其中 `detections` 应大于 0。建议每张尽量看到全部 12 个标签；局部入镜可以用于增强边缘覆盖，但不能让大多数图片只看到很少的标签。

**必须覆盖：**

1. 板卡位于画面中心、左、右、上、下；
2. 近、中、远三种距离，且标签仍清晰可辨；
3. 绕水平轴和垂直轴分别做正、负倾斜；
4. 板卡完全静止后再采集，避免运动模糊；
5. 不改变焦距、对焦、分辨率、binning、ROI 或镜头光圈。

**采集后查询状态：**

```bash
curl --fail http://127.0.0.1:8080/api/calibration \
  | python3 -m json.tool
```

**通过结果：** `captures` 中有 12 至 20 条记录，至少 3 条的 `detections` 大于 0；`coverage` 中 `x`、`y`、`size`、`skew` 不应全部接近 0。

### 步骤 7：一键标定

**操作：** 采集完成后点击"一键标定"按钮。页面会弹出参数确认对话框，填入步骤 2 实测的 `tag_size_m` 和 `tag_spacing_m`，确认后提交。

**HTTP 等价：**

```bash
curl -X POST http://127.0.0.1:8080/api/calibration/start \
  -H 'Content-Type: application/json' \
  -d '{
    "rows": 4,
    "cols": 3,
    "tag_size_m": 0.05,
    "tag_spacing_m": 0.01,
    "tag_family": "tag36h11",
    "max_reprojection_error": 2.0,
    "timeout_s": 300
  }'
```

**通过结果：**

页面实时显示标定进度：检测阶段显示 `images_processed`，求解阶段显示当前 RANSAC 状态。完成后显示：

- `success: true`；
- `images_used >= 3`（生产建议 >= 12）；
- `reprojection_error <= 2.0`；
- 内参矩阵 K、畸变系数 D、图像尺寸；
- 去畸变预览对比图。

**失败说明：**

- 检测图片不足 3 张 → 回去补采集；
- RMS 超过阈值 → 删除模糊/重复/误检图，增加边缘/倾斜/远近覆盖；
- 超时 → 检查图片数量与性能，必要时提高 `timeout_s`。

### 步骤 8：应用内参

**操作：** 标定成功后，页面显示"应用内参"按钮。点击后 Dashboard 将结果 YAML 写入相机配置引用的 `camera_info_url` 路径，并校验文件有效性。

**HTTP 等价：**

```bash
# 先查当前可用的结果文件
curl http://127.0.0.1:8080/api/calibration | python3 -m json.tool
# 取 result.filename 字段
curl -X POST http://127.0.0.1:8080/api/calibration/apply \
  -H 'Content-Type: application/json' \
  -d '{"filename": "calibration_20260902_153000.yaml"}'
```

**通过结果：**

- 返回 `{"applied": true, "camera_info_url": "..."}`；
- 返回的 `camera_info_url` 与相机 YAML 中配置的一致；
- 无需手动复制文件或重新构建包。

**失败说明：**

- 文件写入权限不足 → 检查 Docker 卷映射或宿主机目录权限；
- `camera_info_url` 解析失败 → 检查相机 YAML 中的 `camera_info_url` 字段是否为有效 `package://` 或绝对路径。

## 4. 闭环复验

### 步骤 9：重启相机并读取 CameraInfo

**终端 B 指令：**

重启流水线（终端 A 先 Ctrl+C 再重新执行步骤 3），然后：

```bash
timeout 10 ros2 topic echo \
  /my_camera/pylon_ros2_camera_node/camera_info --once
```

**通过结果：**

- `width`、`height` 与标定 YAML 一致；
- `distortion_model: plumb_bob`；
- `k`、`d`、`r`、`p` 与 YAML 对应；
- `k[0]`、`k[4]` 不是 `0` 或接近 `1` 的占位值。

### 步骤 10：检查内参诊断和校正图像

**指令：**

```bash
timeout 10 ros2 topic echo /my_camera/diagnostics \
  --field status --once \
  | grep -A8 intrinsic_calibration
ros2 topic info \
  /my_camera/pylon_ros2_camera_node/image_rect --verbose
timeout 10 ros2 topic hz \
  /my_camera/pylon_ros2_camera_node/image_rect
```

**通过结果：**

- 内参诊断为 `OK`，消息包含 `Intrinsic calibration found`；
- `image_rect` 的 `Publisher count` 至少为 1；
- 能统计到稳定频率。

**说明：** 只有订阅者存在时，相机组件才可能实际发布校正图像。运行 `ros2 topic hz` 本身会建立订阅。

### 步骤 11：检查校正画面质量

用 RViz2 或 `rqt_image_view` 对比原始图和校正图：

```bash
ros2 run rqt_image_view rqt_image_view \
  /my_camera/pylon_ros2_camera_node/image_rect
```

**通过结果：**

- 直线在校正后更接近直线，尤其是画面边缘；
- 图像无明显不对称拉伸、翻转或大面积异常黑区；
- 静止物体边缘稳定，无分辨率错配造成的畸变。

至此，Web 向导标定、结果应用、`camera_info` 和 `image_rect` 全部通过，才判定内参标定功能闭环验证成功。

## 5. 常见失败与定位

| 现象或结果 | 含义 | 处理方法 |
| --- | --- | --- |
| 点击"启动标定"无反应 | Dashboard 后端异常 | 检查容器日志、`/api/calibration/service` 是否返回 running=false |
| "No calibration images found" | 采集会话无图片 | 检查会话状态、重新采集 |
| "Need at least 3 calibration images with visible AprilTags" | 有效检测图片不足 3 张 | 改善曝光、对焦、板卡尺寸并重新采集 |
| `last_detection_count: 0` | 当前图片未检测到板卡 | 检查 `tag36h11`、ID、清晰度、反光和打印边框 |
| 标定成功但 RMS 超过阈值 | 采样质量差 | 删除模糊、重复或误检图，增加边缘/倾斜/远近覆盖 |
| "应用内参"返回权限错误 | 输出目录无写权限 | 检查 Docker 卷映射或宿主机 `calibration_dir` 权限 |
| 有 `camera_info` 但无 `image_rect` | 内参未被认可或没有订阅者 | 查诊断，并用 `ros2 topic hz image_rect` 建立订阅 |
| 校正后画面更差 | 分辨率或相机光学设置不一致 | 固定设置后重新标定 |
