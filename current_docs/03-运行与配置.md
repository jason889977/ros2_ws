# 运行与配置

## 1. 统一生产入口

### Docker（生产环境推荐）

```bash
docker compose up
```

容器启动时 `entrypoint.sh` 自动清理残留进程和端口，无需手动干预。

### 裸机测试

**推荐使用 wrapper 脚本**，自动清理残留进程并在退出时确保子进程一起退出：

```bash
./deploy/basler_camera/run_pipeline.sh enable_keyence:=false
```

该脚本在启动前 `pkill` 残留的 `component_container`、`web_dashboard`、`aprilgrid_calibration_server` 等进程并释放 8080 端口；Ctrl+C 时通过 `trap` 正确传播信号并清理子进程。

也可直接 `ros2 launch`（但需自行确保无残留进程）：

```bash
source /opt/ros/humble/setup.bash
source /home/ubuntu/ros2_ws/install/setup.bash
ros2 launch industrial_vision_bringup vision_pipeline.launch.py
```

### 默认启动的节点

- Basler 相机组件（容器内）；
- AprilTag 组件与位姿读取节点；
- Keyence 节点；
- 状态聚合器；
- 事件日志节点；
- Web Dashboard。

## 2. Launch 参数

| 参数 | 默认值 | 说明 |
| ------ | -------- | ------ |
| `camera_id` | `my_camera` | 流水线命名空间，必须为合法 ROS 标识符 |
| `camera_config` | 安装区的 `aca2500_106611_18.yaml` | 相机参数 YAML |
| `camera_frame` | `basler_aca2500_106611_18` | 相机 TF frame |
| `startup_user_set` | `Default` | 相机启动 User Set |
| `mtu_size` | `1500` | 相机网络 MTU，允许 576 至 9000 |
| `respawn` | `true` | 组件容器和独立硬件节点异常退出后重启 |
| `scanner_ip` | `172.31.0.91` | Keyence 地址 |
| `scanner_port` | `9004` | Keyence TCP 端口，允许 1 至 65535 |
| `reconnect_interval_s` | `5.0` | 扫码器重连周期，必须有限且不小于 0 |
| `binning_x` / `binning_y` | `0` | 0 表示沿用相机 YAML；正值覆盖 YAML |
| `apriltag_ids` | 空 | 逗号分隔 ID；空表示 0 至 11 |
| `apriltag_size` | `0.0` | 0 表示使用 0.05 m |
| `enable_apriltag` | `true` | 启用 AprilTag 检测链 |
| `enable_keyence` | `true` | 启用 Keyence 节点 |
| `handeye_calibration_file` | 空 | 非空时加载手眼 YAML 并发布静态 TF |
| `world_frame` / `base_frame` | 空 | 两者都非空时发布 world 到 base 的静态锚点 |
| `web_port` | `8080` | Dashboard 本机端口 |
| `enable_web_dashboard` | `true` | 启用 Dashboard |
| `archive_dir` | 空 | Dashboard 快照归档目录 |
| `event_log_dir` | `/var/log/vision` | JSON Lines 事件目录（需写入权限） |
| `calibration_dir` | `/tmp/vision_calibration` | 标定页面的采集图、结果和历史归档目录 |
| `handeye_calibration_dir` | 空（实际取值 `$calibration_dir/handeye`） | 手眼标定采集图与结果目录；空则落到 `calibration_dir/handeye` |
| `handeye_calibration_file` | 空 | 非空时加载手眼 YAML 并发布静态 TF，同时是「应用手眼」写入的目标路径 |
| `params_file` | 空 | 给状态、日志和 Dashboard 节点追加的 ROS 参数文件 |

示例：只运行相机与 AprilTag：

```bash
ros2 launch industrial_vision_bringup vision_pipeline.launch.py \
  camera_id:=line_camera \
  camera_config:="$PWD/deploy/basler_camera/config/aca2500_106611_18.yaml" \
  enable_apriltag:=true \
  enable_keyence:=false
```

## 3. 参数覆盖规则

统一 launch 把显式 launch 参数转换为节点参数。环境变量只用于部分 launch 参数的默认值；显式 `name:=value` 优先。

`params_file` 仅追加到以下节点：

- `vision_status_aggregator`；
- `event_logger`；
- `web_dashboard`。

它不会自动覆盖相机组件、AprilTag 组件或 Keyence 节点。硬件和检测器参数应使用对应 launch 参数或相机/检测器 YAML。

## 4. 相机配置

本地 launch 默认读取安装后的 `pylon_ros2_camera_wrapper` 配置。容器 entrypoint 默认传入：

```text
/opt/ros2_ws/deploy/basler_camera/config/aca2500_106611_18.yaml
```

容器运行时该目录由宿主机 `deploy/basler_camera/config/` 只读挂载。修改现场参数后需要重启容器；修改镜像内源码配置不会覆盖宿主机挂载内容。

`binning_x=0` 和 `binning_y=0` 表示不向组件传入覆盖值，由相机 YAML 决定。默认 Basler 配置使用 `1x1` 分箱以保持 AprilTag 视野与校正图像分辨率，并请求 `frame_rate: 14.0`；现场可在相机 YAML 中按网络带宽、曝光时间和处理负载调整这些值。

## 5. 话题拓扑

对 `camera_id=my_camera`：

| 功能 | 路径 |
| ------ | ------ |
| 原始图像 | `/my_camera/pylon_ros2_camera_node/image_raw` |
| 校正图像 | `/my_camera/pylon_ros2_camera_node/image_rect` |
| 相机内参 | `/my_camera/pylon_ros2_camera_node/camera_info` |
| AprilTag 检测 | `/my_camera/detections` |
| AprilTag Pose | `/my_camera/apriltag/pose` |
| AprilTag Transform | `/my_camera/apriltag/transform` |
| Keyence 文本 | `/my_camera/scanner/barcode` |
| Keyence 触发 | `/my_camera/scanner/trigger` |
| 诊断 | `/my_camera/diagnostics` |
| 汇总状态 | `/my_camera/vision/status` |

`image_rect` 不是无条件输出：Basler 组件成功加载 `camera_info_url` 后才初始化校正链。AprilTag 订阅该话题，因此有效相机内参是生产 AprilTag 检测链的前置条件。

> Dashboard 手眼标定向导会额外订阅**全局** `/apriltag/transform`（去掉命名空间前缀）
> 以保持与 AprilTag Pose 节点默认输出一致。若 AprilTag 组件使用自定义命名空间变换话题，
> 需要确保有同名的无命名空间话题（如通过 topic 桥接）。

## 6. 模块开关与期望诊断

状态聚合器根据启用模块构造期望组件：

- 相机始终是期望组件；
- `enable_apriltag=true` 时要求 AprilTag 位姿节点诊断；
- `enable_keyence=true` 时要求扫码器连接诊断。

启用但无新鲜诊断会使汇总状态进入 ERROR。不要只停止节点而保留对应功能开关。

## 7. 事件与归档

事件日志文件名：

```text
{event_log_dir}/{camera_id}_events.jsonl
```

默认单文件上限 50 MiB，保留 5 个轮转文件。记录包含 UTC 时间、相机 ID、事件类型和事件数据。

> **裸机注意：** 默认 `event_log_dir=/var/log/vision` 需要写入权限。裸机运行前执行：
>
> ```bash
> sudo mkdir -p /var/log/vision && sudo chmod 777 /var/log/vision
> ```
>
> Docker 容器内由 entrypoint 自动创建并授权。

## 8. Dashboard

Dashboard 启动后：

- 页面：`http://127.0.0.1:{web_port}/`；
- OpenAPI：`http://127.0.0.1:{web_port}/api/docs`；
- 存活探针：`http://127.0.0.1:{web_port}/health`。

当前服务仅监听 `127.0.0.1`。需要远程访问时，应通过明确受控的代理或隧道暴露。

### 8.1 端口冲突快速失败

启动前检测 `web_port` 是否被占用。若端口已被占用（残留进程、前次未正常退出等），Dashboard 节点输出 `FATAL` 日志后立即退出，而非静默运行一个无响应的服务。使用 `run_pipeline.sh` 或 Docker entrypoint 可自动清理占用端口的残留进程。

### 8.2 相机内参标定向导

Dashboard 提供 AprilGrid 四步向导：**启动标定 → 引导拍照 → 一键标定 → 应用内参**。仅通过此路径执行内参标定；页面会自动管理 `aprilgrid_calibration_server` 进程生命周期。

- 前置条件：AprilTag 检测链运行，且 `image_rect` 持续发布（即已加载有效初始相机内参）；
- 采集图落到 `$calibration_dir/sessions/<session_id>/`，YAML 与去畸变预览落到 `$calibration_dir/history/`；
- 「应用内参」会将标定 YAML 复制覆盖到 `camera_config` 引用的 `camera_info_url` 路径，并通过 SetCameraInfo 服务热更新组件。

操作细节见 [06-标定与TF.md](06-标定与TF.md) 第 2 节。

### 8.3 手眼标定向导（机械臂零通信）

Dashboard 新增「手眼标定（眼在手上）」四步向导：**配置参数 → 采集样本 → 一键求解 → 应用结果**。该向导**不直接与机械臂通信**：机器人位姿通过 6 维手动输入框（`X/Y/Z` mm + `Roll/Pitch/Yaw` °，约定 xArm 控制位姿格式）由现场工程师在移动机械臂后手动录入；AprilTag 位姿由 ROS 订阅自动同步。

前置条件：

- 流水线已启动，AprilTag 板卡位于画面中（页面顶部「标签位姿就绪」状态为绿色）；
- launch 参数 `handeye_calibration_file` 指向 TF 广播器使用的同一 YAML 路径（否则「应用结果」会提示未配置）；
- `enable_apriltag=true`（全局 `/apriltag/transform` 有持续输出）。

四步流程：

1. **配置参数**：算法（`tsai`/`park`/`horaud`/`daniilidis`）、4 个 TF 帧名（base/gripper/camera/target）、闭环最大平移（默认 1.0 mm）与旋转阈值（默认 0.5°）；点击「启动标定」创建新会话。
2. **采集样本**：机械臂移动到一组姿态 → 在输入框填 6 维位姿 → 点击「采集样本」。页面显示 10 组引导姿态（三轴平移 + 三轴旋转 + 混合姿态），实时提示「平移跨度≥20mm / 旋转跨度≥15°」的多样性指标。提供「填入上次」按钮便于上一组微调。**至少 4 组**、生产建议 10+ 组。
3. **一键求解**：后台线程调用 `vision_core.solve_hand_eye()`，通过闭环误差阈值门禁后写出 OpenCV FileStorage YAML 与结果 JSON。
4. **应用结果**：将 YAML 复制覆盖到 `handeye_calibration_file` 路径，并调用 `/{camera_id}/handeye_static_tf_broadcaster/reload_calibration` 热重载 TF 广播器。

文件落盘：

- 样本图 → `$handeye_calibration_dir/sessions/<session_id>/sample_XXX.jpg`
- YAML / JSON / 预览图 → `$handeye_calibration_dir/history/`
- 目标生效文件 → `handeye_calibration_file` 参数指向的路径

若 launch 中同时传了 `handeye_calibration_file`，TF 广播器已作为流水线节点启动，应用结果后无需重启流水线即可生效。

> 离线求解 CLI（`handeye_calibrate`）仍保留在 `handeye_calibration`
> 包中，适合对 Web 会话导出的 CSV 重新求解；Online Action 方式已移除。
> 详情见 [06-标定与TF.md](06-标定与TF.md) 第 5、6、7 节。
