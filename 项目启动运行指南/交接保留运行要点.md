# 交接保留运行要点

本文件保留已删除交接资料中仍适用于当前项目、但未被其他文档完整覆盖的运行与验收要点。

日常启动和停止以[快速启动指南](项目启动运行指南/快速启动指南.md)为准；生产部署和完整验收以[部署与开发操作手册](部署与开发操作手册.md#9-ros-2-运行验证与验收)为准；Basler 构建、部署和故障处理以[Basler 相机构建部署与故障处理 SOP](项目启动运行指南/Basler相机构建部署与故障处理SOP.md)为准；话题、服务和 TF 契约以[Basler ROS 2 接口](deploy/basler_camera/ROS2-INTERFACE.md)为准。

## Keyence 在线切换与恢复

`/my_camera/keyence_sr_node` 支持在运行时更新 `scanner_ip` 和 `scanner_port`。节点只在能够连接到新地址时接受变更；连接失败时保留当前有效配置。断线后，后台按 `reconnect_interval_s` 检查并尝试恢复连接。

调用 `/my_camera/scanner/trigger` 时，以下返回代表失败或需等待恢复：

- `Scanner not connected.`：节点当前没有可用的扫码器连接。
- `Timeout: Scanner did not respond in time.`：设备未在超时内响应。
- `Scanner Error: ER...` 或 `Communication Error: ...`：设备或 TCP 通信异常。

统一 pipeline 已经管理 Keyence 节点。不要在同一容器中额外单独启动节点，以免两个实例争用同一设备或 ROS 名称。

## 更换 Basler 相机检查单

更换 GigE 相机后，按以下顺序恢复：

1. 枚举相机并确认物理网络可达；必要时使用 `pylon_ip_auto_config` 配置 IP 与子网掩码。
2. 通过新相机序列号设置既有 `device_user_id`；若更换名称，同时更新相机 YAML 中的 `device_user_id`。
3. 将 `CAMERA_CONFIG_FILE` 指向对应 YAML，并确认 YAML 中的设备身份与新的绑定一致。
4. 用容器内图像话题的实际消息确认采集链路，而不是只检查节点是否存在。

不要让宿主机手动启动的 Basler 节点与容器内 pipeline 同时连接同一相机。

## 交付验收门禁

### 图像吞吐

验收必须确认 ROS 2 订阅方实际收到图像消息。分别记录：

- 容器日志中的 `Image publish FPS`，即驱动侧发布计数。
- `ros2 topic hz /my_camera/pylon_ros2_camera_node/image_raw`，即订阅端实际到达率。

两个指标统计位置不同，不要求相等；仅看到 publisher 或节点存在不能视为验收通过。

### 抓取错误

连续或重复出现下列日志时，判定采集链路未通过验收，应检查网络、相机连接与采集配置：

- `3774873620`
- `incompletely grabbed`
- `Grab was not successful`

生产部署优先检查容器日志：

```bash
docker logs basler_camera 2>&1 | grep -Ei '3774873620|incompletely grabbed|Grab was not successful'
```

### AprilTag 最小链路

对 AprilTag 交付验收，至少验证 `/my_camera/detections`、`/my_camera/apriltag/pose` 和 `/my_camera/apriltag/transform` 均有实际输出。读取 `transform` 的 `header.frame_id` 与 `child_frame_id` 后，用 `tf2_echo` 验证连续变换，并记录这对父子 frame。

## 当前默认与历史快照

统一 pipeline 的 `prefer_wechat_qr` 当前默认值是 `true`。设为 `false` 仅用于无模型或定位二维码识别稳定性问题的排障场景。

旧交接资料中的特定分辨率、帧率、AprilTag `decision_margin`、标签 ID，以及主机 apt、Python 或 OpenCV 版本都是当时现场条件下的快照，不构成当前部署要求。实际验收应以当前配置、容器镜像和现场光照、曝光、距离、角度及标定状态为准。
