# ROS 2 工业视觉部署与开发操作手册

适用项目：Basler GigE 相机、AprilTag、二维码识别和 Keyence SR 扫码器统一视觉系统

适用环境：Ubuntu 22.04 LTS、ROS 2 Humble、Docker Compose v2

工作区：`/home/ubuntu/ros2_ws`

本文面向现场运维人员、ROS 2 开发人员和机器人集成人员，覆盖配置编辑、本地编译测试、Docker 镜像构建、容器运行、ROS 2 联调、日常维护和常见故障排查。

---

## 1. 先看这里：最短启动路径

生产环境推荐使用一个 `basler_camera` Docker 容器统一运行全部视觉节点。不要在宿主机同时启动相机节点，否则可能出现相机被占用。

在首次部署前，确认已经准备好 Basler pylon SDK，然后执行：

```bash
cd /home/ubuntu/ros2_ws

cp deploy/basler_camera/.env.example deploy/basler_camera/.env

# 编辑现场配置
code deploy/basler_camera/.env

# 构建镜像
DOCKER_BUILDKIT=1 docker build \
  -f deploy/basler_camera/Dockerfile \
  -t basler_camera_20260825_v1.0 .

# 启动容器
sudo -n docker compose \
  --env-file deploy/basler_camera/.env \
  -f deploy/basler_camera/docker-compose.yml \
  up -d

# 查看运行状态
sudo -n docker inspect \
  --format '{{.State.Status}} {{.State.Health.Status}}' \
  basler_camera
```

首次启动后，期望看到：

```text
running starting
```

等待约 20 至 40 秒后再次检查，最终应为：

```text
running healthy
```

如果最终不是 `running healthy`，先查看日志：

```bash
sudo -n docker logs --tail=200 basler_camera
```

## 2. 运行模式与命令执行位置

### 2.1 生产模式

生产环境统一使用：

- Compose 文件：`deploy/basler_camera/docker-compose.yml`
- 环境文件：`deploy/basler_camera/.env`
- 镜像：由 `deploy/basler_camera/Dockerfile` 构建
- 容器：默认名为 `basler_camera`
- 启动入口：`industrial_vision_bringup/vision_pipeline.launch.py`

生产运行、重启、停止和验收都围绕这个容器进行。

### 2.2 开发调试模式

开发时可以在宿主机使用 ROS 2 工作区进行编译、测试和手动 launch。手动启动相机前必须先停止生产容器：

```bash
sudo -n docker stop basler_camera
```

开发调试结束后，不要让宿主机节点和 Docker 容器同时连接同一台相机。

### 2.3 命令执行位置

本文命令默认分为两类：

- **宿主机命令**：在工控机或开发机终端执行，当前目录通常是 `/home/ubuntu/ros2_ws`。
- **容器内命令**：通过 `docker exec` 执行，工作区路径是 `/opt/ros2_ws`。

路径不能混用：

| 用途 | 宿主机路径 | 容器内路径 |
|---|---|---|
| 工作区 | `/home/ubuntu/ros2_ws` | `/opt/ros2_ws` |
| 源码 | `/home/ubuntu/ros2_ws/src` | `/opt/ros2_ws/src` |
| 容器配置挂载目录 | `/home/ubuntu/ros2_ws/deploy/basler_camera/config` | `/opt/ros2_ws/deploy/basler_camera/config` |
| ROS 2 Humble | 通常为 `/opt/ros/humble` | `/opt/ros/humble` |
| 工作区安装空间 | `/home/ubuntu/ros2_ws/install` | `/opt/ros2_ws/install` |

例如，`CAMERA_CONFIG_FILE` 应填写容器内路径：

```dotenv
CAMERA_CONFIG_FILE=/opt/ros2_ws/deploy/basler_camera/config/aca2500_106611_18.yaml
```

不能填写：

```dotenv
CAMERA_CONFIG_FILE=/home/ubuntu/ros2_ws/deploy/basler_camera/config/aca2500_106611_18.yaml
```

## 3. 首次部署前检查

### 3.1 检查操作系统、Docker 和 ROS 2

```bash
lsb_release -a
docker --version
docker compose version
source /opt/ros/humble/setup.bash
ros2 --version
```

Docker Compose 需要支持 `docker compose` 子命令。若只有旧版 `docker-compose`，应先安装或升级 Compose v2。

### 3.2 检查工作区和 pylon SDK

```bash
cd /home/ubuntu/ros2_ws
test -d src
test -f deploy/basler_camera/Dockerfile
test -d deploy/basler_camera/pylon-sdk
ls -lh deploy/basler_camera/pylon-sdk/
```

Dockerfile 会从 `deploy/basler_camera/pylon-sdk/` 读取 Basler pylon SDK。SDK 受厂商许可限制，通常不提交到 Git 仓库。目录中必须放入交付方提供的、与当前架构匹配的 pylon 8.0 SDK 文件。

当前 Dockerfile 支持以下形式：

- Basler Debian 包 bundle 的 `.tar.gz`
- Basler setup archive 的 `*_setup.tar.gz`
- 直接提供的 `.deb` 文件

如果目录为空，Docker 构建会失败，不能仅靠安装 ROS 2 依赖解决。

### 3.3 检查设备网络

根据现场实际 IP 检查相机和 Keyence：

```bash
ping -c 5 172.31.0.88
ping -c 5 172.31.0.91
```

网络检查失败时，先处理网卡、IP 地址、子网掩码、防火墙、交换机和设备供电问题，再进行软件排查。

## 4. 编辑配置文件

### 4.1 创建环境文件

不要直接修改 `.env.example` 作为生产配置。先复制一份：

```bash
cd /home/ubuntu/ros2_ws
cp deploy/basler_camera/.env.example deploy/basler_camera/.env
```

使用 VS Code 或终端编辑：

```bash
code deploy/basler_camera/.env
```

```bash
nano deploy/basler_camera/.env
```

`.env` 是现场实际配置，`.env.example` 是可提交到仓库的模板。现场 `.env` 可能包含设备 IP、设备身份等信息，不要未经确认提交到公开仓库。

### 4.2 编辑规则

- 等号两边不要添加空格，例如使用 `CAMERA_ID=my_camera`。
- 布尔值使用 `true` 或 `false`。
- 端口必须是 `1` 至 `65535` 的整数。
- `RECONNECT_INTERVAL_S` 必须是大于等于 `0` 的有限数值。
- 路径使用 Linux `/`，不能写 Windows 路径。
- 容器配置路径使用 `/opt/ros2_ws/...`。
- 修改前先备份 `.env`。
- 修改后必须重新解析或重新创建 Compose 容器，旧容器不会自动读取新变量。

备份配置：

```bash
cp deploy/basler_camera/.env \
  deploy/basler_camera/.env.backup.$(date +%Y%m%d_%H%M%S)
```

恢复配置：

```bash
cp deploy/basler_camera/.env.backup.YYYYMMDD_HHMMSS \
  deploy/basler_camera/.env
```

### 4.3 单相机常用配置

下面是常见的单相机配置示例。IP、设备身份和功能开关应按现场实际情况修改：

```dotenv
BASLER_IMAGE=basler_camera_20260825_v1.0
BASLER_CONTAINER_NAME=basler_camera

ROS_DOMAIN_ID=0
RMW_IMPLEMENTATION=rmw_fastrtps_cpp

CAMERA_ID=my_camera
CAMERA_CONFIG_FILE=/opt/ros2_ws/deploy/basler_camera/config/aca2500_106611_18.yaml
CAMERA_FRAME=basler_aca2500_106611_18
CAMERA_MTU_SIZE=1500
CAMERA_STARTUP_USER_SET=Default
CAMERA_RESPAWN=true
CAMERA_STARTUP_TIMEOUT_S=120

ENABLE_APRILTAG=true
ENABLE_QRCODE=false
ENABLE_KEYENCE=true

SCANNER_IP=172.31.0.91
SCANNER_PORT=9004
RECONNECT_INTERVAL_S=5.0
```

当前仓库中的 `.env` 和 `.env.example` 的二维码默认值可能不同。运行时以实际使用的 `deploy/basler_camera/.env` 为准：`ENABLE_QRCODE=false` 时，二维码节点不启动，也不应把二维码话题缺失判定为故障。

### 4.4 主要参数说明

| 参数 | 作用 | 注意事项 |
|---|---|---|
| `BASLER_IMAGE` | Compose 使用的镜像 tag | 必须与实际构建的 tag 一致 |
| `BASLER_CONTAINER_NAME` | 容器名称 | 运维脚本默认使用 `basler_camera` |
| `ROS_DOMAIN_ID` | ROS 2 DDS 域 | 容器与宿主机、机器人程序应一致 |
| `RMW_IMPLEMENTATION` | DDS 实现 | 当前默认 `rmw_fastrtps_cpp` |
| `CAMERA_ID` | 相机 ROS 命名空间 | 默认话题前缀为 `/my_camera` |
| `CAMERA_CONFIG_FILE` | 容器内相机 YAML 路径 | 必须使用容器内路径 |
| `CAMERA_FRAME` | 相机图像 frame | 双相机时必须互不相同 |
| `CAMERA_MTU_SIZE` | GigE MTU | 只有网络和相机都支持时才改 Jumbo Frame |
| `CAMERA_STARTUP_USER_SET` | 相机 User Set | 常用 `Default`、`CurrentSetting`、`UserSet1` |
| `CAMERA_RESPAWN` | 相机节点异常后是否重启 | 生产环境通常保持 `true` |
| `CAMERA_STARTUP_TIMEOUT_S` | 等待 `camera_info` 的最大秒数 | 超时通常表示相机未连接、被占用或配置错误 |
| `ENABLE_APRILTAG` | 启用 AprilTag 链路 | 启用后健康检查要求节点存在 |
| `ENABLE_QRCODE` | 启用二维码链路 | 启用后健康检查要求二维码节点存在 |
| `ENABLE_KEYENCE` | 启用 Keyence 链路 | 启用后健康检查要求扫码节点存在 |
| `SCANNER_IP` | Keyence IP 地址 | 按现场设备修改 |
| `SCANNER_PORT` | Keyence TCP 端口 | 必须为 `1` 至 `65535` |
| `RECONNECT_INTERVAL_S` | Keyence 重连间隔 | 必须为不小于 `0` 的数值 |
| `HANDEYE_CALIBRATION_FILE` | 手眼标定 YAML 路径 | 启用后自动发布 `tool0 -> camera` 静态 TF |
| `WORLD_FRAME` | 全局坐标系 frame | 如 `world`，用于多相机/机器人全局统一锚定 |
| `BASE_FRAME` | 机器人基座 frame | 如 `base_link`，与 `WORLD_FRAME` 配合使用 |
| `PREFER_WECHAT_QR` | 是否优先使用 WeChatQR | 模型不完整时应关闭或确认模型文件存在 |
| `MEM_LIMIT` | 容器内存限制 | 默认 `4g` |
| `CPUS_LIMIT` | 容器 CPU 限制 | 默认 `4.0` |
| `LOG_MAX_SIZE` | 单个 Docker 日志文件大小 | 默认 `50m` |
| `LOG_MAX_FILE` | 日志文件保留数量 | 默认 `3` |

### 4.5 双相机配置

设置 `CAMERA_ID_2` 后会启用第二条 pipeline。第二路至少需要配置：

```dotenv
CAMERA_ID_2=cam2
CAMERA_CONFIG_2=/opt/ros2_ws/deploy/basler_camera/config/cam2.yaml
CAMERA_FRAME_2=basler_cam2
ENABLE_APRILTAG_2=true
ENABLE_QRCODE_2=false
ENABLE_KEYENCE_2=false
```

双相机必须满足：

- `CAMERA_ID_2` 与 `CAMERA_ID` 不同。
- `CAMERA_CONFIG_2` 与 `CAMERA_CONFIG_FILE` 不同。
- 两个物理相机必须有不同的设备身份。
- 若第二路启用 AprilTag，`CAMERA_FRAME_2` 必须与 `CAMERA_FRAME` 不同。
- Keyence 的第二路 IP、端口和重连参数按现场设备配置。
- 两路的输出话题分别位于 `/<CAMERA_ID>/...` 和 `/<CAMERA_ID_2>/...`。

留空 `CAMERA_ID_2` 即关闭双相机：

```dotenv
CAMERA_ID_2=
```

### 4.6 修改 YAML 或标定配置

相机运行参数位于：

```text
src/pylon_ros2_camera_wrapper/config/
deploy/basler_camera/config/
```

生产 Docker 镜像会复制 `deploy/basler_camera/config/`，Compose 运行时又会把宿主机的同名 `config` 目录以只读方式挂载到容器中。因此，生产现场修改配置后，优先修改：

```text
deploy/basler_camera/config/*.yaml
```

源码开发或手动 launch 使用的是：

```text
src/pylon_ros2_camera_wrapper/config/*.yaml
```

如果两套配置都要保持一致，应同步修改并记录变更。标定完成后，不要继续使用默认占位内参；确认 `camera_info` 中的 `fx`、`fy` 等值是真实标定结果。

## 5. 修改内容与后续操作对照

| 修改内容 | 后续操作 |
|---|---|
| 只修改 `.env` | 重新执行 `docker compose up -d`；必要时加 `--force-recreate` |
| 修改 `deploy/basler_camera/config/*.yaml` | 重新创建或重启容器，使节点重新读取配置 |
| 修改 `src` 中的 Python 代码 | 本地重新编译；生产环境重新构建镜像 |
| 修改 C++ 代码 | 本地重新编译；生产环境重新构建镜像 |
| 修改 launch 文件 | 本地重新编译；生产环境重新构建镜像 |
| 修改 Dockerfile | 重新构建镜像 |
| 修改 `docker-compose.yml` | 重新执行 Compose；必要时加 `--force-recreate` |
| 修改镜像 tag | 同步修改 `.env` 中的 `BASLER_IMAGE` |
| 修改模型文件 | 确认模型路径和文件完整，再重启或重建对应运行环境 |

配置文件通过 volume 挂载并不代表正在运行的节点会自动重新加载。修改后应重新创建容器，不能只观察宿主机文件时间变化。

## 6. ROS 2 本地开发、编译与测试

### 6.1 加载环境

每个新的终端都执行：

```bash
cd /home/ubuntu/ros2_ws
source /opt/ros/humble/setup.bash
```

工作区已经成功构建后，再执行：

```bash
source install/setup.bash
```

如果 `install/setup.bash` 不存在或 source 报错，说明工作区尚未成功构建，先执行编译。

### 6.2 全量 Release 编译

```bash
cd /home/ubuntu/ros2_ws
source /opt/ros/humble/setup.bash
colcon build --symlink-install \
  --cmake-args -DCMAKE_BUILD_TYPE=Release
source install/setup.bash
```

说明：

- `colcon build` 编译工作区中的 ROS 2 包。
- `--symlink-install` 适合开发，Python 文件和资源修改后更容易生效。
- `Release` 模式适合现场运行。
- C++ 修改后必须重新编译。

### 6.3 按包编译

只修改某个功能时，可以缩小范围：

```bash
colcon build --symlink-install \
  --packages-select qrcode_detector \
  --cmake-args -DCMAKE_BUILD_TYPE=Release
source install/setup.bash
```

常用包组合：

```bash
colcon build --symlink-install \
  --packages-select \
  pylon_ros2_camera_interfaces \
  apriltag_pose_reader \
  keyence_sr_wrapper \
  qrcode_detector \
  industrial_vision_bringup \
  --event-handlers console_direct+
source install/setup.bash
```

如果修改了接口定义，先编译 `pylon_ros2_camera_interfaces`，再编译依赖它的包。遇到依赖关系或安装空间异常时，使用全量编译确认问题。

### 6.4 运行 Python 单元测试

```bash
cd /home/ubuntu/ros2_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
python3 -m pytest \
  src/keyence_sr_wrapper/test/ \
  src/apriltag_pose_reader/test/ \
  src/qrcode_detector/test/ \
  src/industrial_vision_bringup/test/ \
  -v
```

### 6.5 运行 colcon 测试

```bash
colcon test \
  --packages-select \
  pylon_ros2_camera_interfaces \
  apriltag_pose_reader \
  keyence_sr_wrapper \
  qrcode_detector \
  industrial_vision_bringup \
  --event-handlers console_cohesion+

colcon test-result --verbose
```

提交或部署前，应保存编译和测试结果。测试失败时先确认失败包、首个错误和是否为环境依赖问题，不要只看最后一行汇总。

### 6.6 编译后的最小检查

```bash
source /opt/ros/humble/setup.bash
source /home/ubuntu/ros2_ws/install/setup.bash

ros2 pkg prefix pylon_ros2_camera_interfaces
ros2 pkg prefix apriltag_pose_reader
ros2 pkg prefix qrcode_detector
ros2 pkg prefix industrial_vision_bringup
```

能返回安装路径，说明这些包已被当前 ROS 2 环境发现。

## 7. Docker 镜像构建

### 7.1 标准构建命令

必须在工作区根目录执行，因为 Dockerfile 需要访问 `src/`、`deploy/` 和 pylon SDK：

```bash
cd /home/ubuntu/ros2_ws

DOCKER_BUILDKIT=1 docker build \
  -f deploy/basler_camera/Dockerfile \
  -t basler_camera_20260825_v1.0 .
```

构建完成后检查镜像：

```bash
docker image ls basler_camera
```

### 7.2 使用 buildx 构建

构建速度较慢或需要明确启用 BuildKit 时：

```bash
docker buildx version

if ! docker buildx inspect ros2-builder >/dev/null 2>&1; then
  docker buildx create --name ros2-builder --driver docker-container --use
else
  docker buildx use ros2-builder
fi

docker buildx inspect --bootstrap
DOCKER_BUILDKIT=1 docker buildx build \
  --progress=plain \
  --load \
  -f deploy/basler_camera/Dockerfile \
  -t basler_camera_20260825_v1.0 .
```

`--load` 会把构建结果加载到本机 Docker 镜像列表，使 Compose 可以直接使用。

### 7.3 替换镜像源

Dockerfile 支持覆盖 Ubuntu 和 ROS 2 apt 源：

```bash
DOCKER_BUILDKIT=1 docker build \
  --build-arg UBUNTU_APT_MIRROR=http://mirrors.aliyun.com/ubuntu \
  --build-arg ROS2_APT_MIRROR=http://mirrors.tuna.tsinghua.edu.cn/ros2/ubuntu \
  -f deploy/basler_camera/Dockerfile \
  -t basler_camera_20260825_v1.0 .
```

基础镜像拉取失败时，可先准备等价的 ROS Humble 基础镜像并按现有 SOP 处理，不要随意更换 ROS 发行版或基础镜像标签。

### 7.4 构建缓存和磁盘空间

Dockerfile 已使用 apt 和 BuildKit 缓存。不要在正常构建前执行 `docker builder prune -f`，否则会删除缓存并重新下载大量依赖。

查看空间：

```bash
docker system df
df -h / /var/lib/docker 2>/dev/null || df -h
```

磁盘确实不足时，再谨慎清理：

```bash
docker builder prune -f
```

pylon SDK 通过 BuildKit bind mount 参与构建，不应被直接 `COPY` 到镜像层。若构建中出现 `No space left on device`，先检查是否错误地把数百 MB 的 SDK 压缩包复制进了镜像。

## 8. 启动、停止和重建容器

### 8.1 首次启动或配置更新

```bash
cd /home/ubuntu/ros2_ws
sudo -n docker compose \
  --env-file deploy/basler_camera/.env \
  -f deploy/basler_camera/docker-compose.yml \
  up -d
```

配置或 Compose 文件修改后，推荐明确重新创建：

```bash
sudo -n docker compose \
  --env-file deploy/basler_camera/.env \
  -f deploy/basler_camera/docker-compose.yml \
  up -d --force-recreate
```

### 8.2 镜像更新后的标准流程

```bash
cd /home/ubuntu/ros2_ws

DOCKER_BUILDKIT=1 docker build \
  -f deploy/basler_camera/Dockerfile \
  -t basler_camera_20260825_v1.0 .

sudo -n docker compose \
  --env-file deploy/basler_camera/.env \
  -f deploy/basler_camera/docker-compose.yml \
  up -d --force-recreate
```

### 8.3 日常启动、重启和停止

日常重启：

```bash
sudo -n docker restart basler_camera
```

停止但保留容器：

```bash
sudo -n docker stop basler_camera
```

启动已有容器：

```bash
sudo -n docker start basler_camera
```

停止并删除 Compose 容器：

```bash
sudo -n docker compose \
  --env-file deploy/basler_camera/.env \
  -f deploy/basler_camera/docker-compose.yml \
  down
```

`docker stop` 只停止容器，不删除容器和镜像。`docker compose down` 会删除 Compose 创建的容器，但不会自动删除镜像。

### 8.4 查看容器状态和配置

```bash
sudo -n docker compose \
  --env-file deploy/basler_camera/.env \
  -f deploy/basler_camera/docker-compose.yml \
  ps

sudo -n docker inspect \
  --format '{{.State.Status}} {{if .State.Health}}{{.State.Health.Status}}{{else}}no-healthcheck{{end}}' \
  basler_camera
```

查看 Compose 最终解析结果：

```bash
sudo -n docker compose \
  --env-file deploy/basler_camera/.env \
  -f deploy/basler_camera/docker-compose.yml \
  config > compose-rendered-config.yml
```

这个命令可以确认 `.env` 是否被正确加载，以及最终的镜像名、环境变量和挂载是否符合预期。输出文件如果包含现场设备信息，不要直接提交到公开仓库。

### 8.5 查看和保存日志

实时查看：

```bash
sudo -n docker logs -f --tail=200 basler_camera
```

保存日志：

```bash
sudo -n docker logs --tail=500 basler_camera \
  > basler_camera_$(date +%Y%m%d_%H%M%S).log
```

保存容器信息：

```bash
sudo -n docker inspect basler_camera \
  > basler_camera_inspect_$(date +%Y%m%d_%H%M%S).json
```

提交日志前检查并删除现场 IP、序列号或其他敏感信息。

## 9. ROS 2 运行验证与验收

### 9.1 容器内环境

在容器内执行 ROS 2 命令时，使用：

```bash
sudo -n docker exec basler_camera bash -lc \
  'source /opt/ros/humble/setup.bash && \
   source /opt/ros2_ws/install/setup.bash && \
   ros2 node list'
```

### 9.2 检查节点

宿主机和容器使用 `network_mode: host`，且 DDS 配置一致时，宿主机可以查看容器中的 ROS 2 节点：

```bash
source /opt/ros/humble/setup.bash
source /home/ubuntu/ros2_ws/install/setup.bash
ros2 node list
```

重点节点包括：

```text
/my_camera/pylon_ros2_camera_node
/my_camera/apriltag_pose_reader
/my_camera/wechat_qr_node
/my_camera/keyence_sr_node
```

被 `.env` 禁用的模块不应要求其节点存在。

### 9.3 检查相机图像和内参

```bash
ros2 topic type /my_camera/pylon_ros2_camera_node/image_raw
ros2 topic type /my_camera/pylon_ros2_camera_node/camera_info
ros2 topic info -v /my_camera/pylon_ros2_camera_node/image_raw
```

持续检查图像频率：

```bash
ros2 topic hz /my_camera/pylon_ros2_camera_node/image_raw
```

读取一条内参：

```bash
ros2 topic echo /my_camera/pylon_ros2_camera_node/camera_info --once
```

正常标准：

- `image_raw` 类型为 `sensor_msgs/msg/Image`。
- `camera_info` 类型为 `sensor_msgs/msg/CameraInfo`。
- 能够实际收到消息，而不仅是话题名称存在。
- 图像格式、分辨率和标定参数符合现场配置。

### 9.4 检查二维码

只有 `ENABLE_QRCODE=true` 时才执行：

```bash
ros2 topic echo /my_camera/qr/decoded_info --once
```

画面中没有二维码时没有结果，不一定表示节点故障。应先确认图像持续发布，再把二维码放入视野检查识别结果。

### 9.5 检查 AprilTag

将配置的 Tag 放入相机视野：

```bash
ros2 topic echo /my_camera/detections --once
ros2 topic echo /my_camera/apriltag/pose --once
ros2 topic echo /my_camera/apriltag/transform --once
```

识别结果会受到 Tag 规格、ID、距离、角度、曝光、内参和 TF 配置影响。图像正常并不保证一定有位姿结果。

### 9.6 检查 Keyence

先监听结果：

```bash
ros2 topic echo /my_camera/scanner/barcode
```

在另一个终端触发一次扫码：

```bash
ros2 service call /my_camera/scanner/trigger \
  std_srvs/srv/Trigger '{}'
```

Keyence 是典型的单次触发链路；二维码和 AprilTag 默认是持续处理图像的链路。

### 9.7 检查诊断和汇总状态

```bash
ros2 topic echo /my_camera/diagnostics --once
ros2 topic echo /my_camera/vision/status --once
```

健康检查会关注：

- 相机 `camera_info` 是否有正确类型并能收到消息。
- 启用的功能节点是否存在。
- `vision/status` 是否报告错误或过期状态。

启用模块的诊断状态为 `ERROR` 或 `STALE` 时，容器可能显示 `unhealthy`。

### 9.8 使用项目自带检查脚本

容器内冒烟测试：

```bash
sudo -n docker exec basler_camera \
  /opt/ros2_ws/deploy/basler_camera/smoke_test.sh
```

期望输出：

```text
SMOKE TEST PASSED: ... is publishing camera_info and image_raw
```

手动执行健康检查：

```bash
sudo -n docker exec basler_camera \
  /opt/ros2_ws/deploy/basler_camera/healthcheck.sh
```

期望输出：

```text
OK
```

## 10. 机器人程序联调注意事项

### 10.1 DDS 环境必须一致

宿主机、视觉容器和机器人程序至少应保持：

```text
ROS_DOMAIN_ID 相同
RMW_IMPLEMENTATION 相同或已确认兼容
```

检查当前终端：

```bash
echo "$ROS_DOMAIN_ID"
echo "$RMW_IMPLEMENTATION"
```

容器环境：

```bash
docker inspect basler_camera \
  --format '{{range .Config.Env}}{{println .}}{{end}}' \
  | grep -E 'ROS_DOMAIN_ID|RMW_IMPLEMENTATION'
```

### 10.2 主要接口

默认相机命名空间为 `/my_camera`。修改 `CAMERA_ID` 后，将前缀替换为对应的相机 ID。

| 功能 | 接口 |
|---|---|
| 原始图像 | `/<camera_id>/pylon_ros2_camera_node/image_raw` |
| 相机内参 | `/<camera_id>/pylon_ros2_camera_node/camera_info` |
| QR 结果 | `/<camera_id>/qr/decoded_info` |
| AprilTag 位姿 | `/<camera_id>/apriltag/pose` |
| AprilTag 变换 | `/<camera_id>/apriltag/transform` |
| Keyence 结果 | `/<camera_id>/scanner/barcode` |
| Keyence 触发 | `/<camera_id>/scanner/trigger` |
| 汇总状态 | `/<camera_id>/vision/status` |

不要只凭话题名称判断链路正常，应使用 `ros2 topic info -v`、`ros2 topic hz` 或 `ros2 topic echo --once` 确认消息实际流动。

### 10.3 查看图像

```bash
/home/ubuntu/ros2_ws/scripts/open_camera_rviz.sh
```

双相机启用 AprilTag 时，必须使用不同的 `CAMERA_FRAME` 和 `CAMERA_FRAME_2`，避免 TF frame 冲突。

## 11. 常见故障快速排查

| 现象 | 优先检查 | 处理方向 |
|---|---|---|
| 容器不断重启 | `docker logs basler_camera --tail=200` | 查看首个错误；重点检查相机、配置和参数格式 |
| 容器 `unhealthy` | healthcheck、节点列表、`vision/status` | 确认相机消息、启用模块和诊断状态 |
| 状态长时间 `starting` | 容器日志和相机网络 | 检查 `CAMERA_STARTUP_TIMEOUT_S`、相机是否连接或被占用 |
| 找不到相机 | 电源、网线、IP、pylon 设备身份 | 确认 YAML 的 `device_user_id` 与实际设备一致 |
| 相机节点存在但无 `image_raw` | `camera_info`、topic 类型和日志 | 检查相机连接、采集参数、设备占用 |
| 有图像但二维码无结果 | 图像内容、二维码距离角度、模块开关 | 确认 `ENABLE_QRCODE=true`、模型和 QR 后端配置 |
| 二维码节点不存在 | `.env` 中 `ENABLE_QRCODE` | 关闭是正常配置；启用后重新创建容器 |
| AprilTag 无位姿 | Tag family/ID、标定、TF | 先检查 `/detections`，再检查 pose 和 transform |
| Keyence 连接失败 | IP、端口、设备电源和网络 | 确认 `SCANNER_PORT` 合法且设备 TCP 服务可达 |
| 宿主机看不到容器话题 | `ROS_DOMAIN_ID`、DDS、网络模式 | 确认容器使用 host 网络且环境变量一致 |
| 修改配置不生效 | Compose 文件、`.env` 和容器创建时间 | 执行 `docker compose config`，再 `up -d --force-recreate` |
| Docker 构建空间不足 | `docker system df`、`df -h` | 检查 SDK 是否被错误 COPY，必要时清理构建缓存 |
| `install/setup.bash` 不存在 | 编译结果和工作区路径 | 回到工作区根目录，先完成 `colcon build` |

### 11.1 相机未发现或设备身份变化

查看容器日志：

```bash
sudo -n docker logs --tail=200 basler_camera
```

若出现设备身份不匹配，先枚举实际相机，再修改 YAML 中的设备身份。更换相机时也可能需要重新绑定设备 User ID：

```bash
/home/ubuntu/ros2_ws/install/pylon_ros2_camera_component/lib/pylon_ros2_camera_component/set_device_user_id \
  -sn <新相机序列号> <新的device_user_id>
```

修改后重新构建或重新启动相机链路，并确认 `CAMERA_CONFIG_FILE` 指向正确配置。

### 11.2 健康检查失败

先手动执行：

```bash
sudo -n docker exec basler_camera \
  /opt/ros2_ws/deploy/basler_camera/healthcheck.sh
```

再查看：

```bash
sudo -n docker inspect --format '{{json .State.Health}}' basler_camera
sudo -n docker logs --tail=300 basler_camera
```

不要通过关闭 healthcheck 来掩盖真实故障。健康检查是发现相机消息中断和启用模块异常的重要保护机制。

## 12. 镜像回滚

生产环境至少保留一个已经验收通过的旧镜像，不要覆盖或立即删除。

查看镜像：

```bash
docker image ls basler_camera
```

编辑 `.env`，切换到旧 tag：

```dotenv
BASLER_IMAGE=basler_camera_20260819_v2.0
```

重新创建容器：

```bash
sudo -n docker compose \
  --env-file deploy/basler_camera/.env \
  -f deploy/basler_camera/docker-compose.yml \
  up -d --force-recreate
```

确认状态：

```bash
sudo -n docker inspect \
  --format '{{.State.Status}} {{.State.Health.Status}}' \
  basler_camera
```

回滚后仍需执行冒烟测试和关键话题验证。

## 14. 生产环境重要注意事项

1. 生产环境统一使用 `basler_camera` 容器，不要混用已经移除或过时的独立容器脚本。
2. 不要让宿主机手动 launch 和 Docker 容器同时连接同一台相机。
3. 不要把宿主机路径写入容器内的 `CAMERA_CONFIG_FILE`。
4. 不要只执行 `docker restart` 来应用新的 Compose 环境变量；配置变化后使用 `docker compose up -d --force-recreate`。
5. 不要随意修改 ROS 2 话题、服务、TF frame 或 camera ID；修改时必须同步机器人侧程序。
6. 不要删除唯一可回滚的旧镜像。
7. 不要随意升级 OpenCV、NumPy 或替换 pip OpenCV 包；当前 QR 与 `cv_bridge` 依赖有明确版本约束。
8. 不要把真实 pylon SDK、现场 `.env`、设备日志和包含现场信息的 Compose 展开文件提交到不受控的位置。
9. 相机、二维码和 AprilTag 的检测结果依赖实际视野、光照、曝光、距离、角度和标定，不能只用“节点存在”作为业务验收标准。
