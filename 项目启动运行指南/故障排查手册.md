# 故障排查手册

本文档提供基于 ROS 2 Humble 工业视觉系统的常见故障现象、定位步骤与解决方案，适用于 Docker 容器部署及本地开发模式。

---

## 1. 相机无法发现或连接失败

### 症状表现
- 容器启动后长时间卡在 `starting` 或健康检查失败（`camera_info` 无数据）。
- 驱动日志输出 `Failed to connect to camera` 或 `No camera found`。

### 排查步骤

```bash
# 1. 确认相机物理连接与网络连通性
ping -c 3 172.31.0.88

# 2. 检查网卡链路与 MTU 配置
ip link show

# 3. 检查配置文件中的相机序列号与 IP
grep -E "serial_number|ip" deploy/basler_camera/config/aca2500_106611_18.yaml

# 4. 确认 pylon SDK 命令行工具能够发现设备
/opt/pylon/bin/pylon_ip_auto_config
```

### 常见原因与解决方案
| 常见原因 | 解决方案 |
|---|---|
| 相机被其他进程或宿主机占用 | 停止宿主机或其它容器中的相机节点，每个物理相机同时只允许单客户端连接 |
| MTU 设置不匹配 | 默认以太网设为 1500；仅在交换机与网卡均开启巨帧时配置为 9000 |
| 配置文件中序列号或 IP 不符 | 校验并更新 [deploy/basler_camera/config/](deploy/basler_camera/config/) 下的实际设备序列号 |
| GigE Vision 端口被防火墙拦截 | 开放 UDP 端口：`sudo ufw allow 3956:3992/udp` |

## 2. AprilTag 无法检测或位姿缺失

### 症状表现
- 话题 `/{camera_id}/apriltag/pose` 与 `/{camera_id}/apriltag/transform` 无数据输出。
- `/{camera_id}/detections` 话题为空。

### 排查步骤

```bash
# 1. 确认相机原始图像流正常发布 (BEST_EFFORT QoS)
ros2 topic hz /{camera_id}/pylon_ros2_camera_node/image_raw

# 2. 确认 AprilTag 检测组件已加载
ros2 node list | grep -E 'apriltag|apriltag_pose_reader'

# 3. 检查标签原始检测消息
ros2 topic echo /{camera_id}/detections --once

# 4. 检查标签配置文件定义
cat src/apriltag_pose_reader/config/apriltag_36h11.yaml
```

### 常见原因与解决方案
| 常见原因 | 解决方案 |
|---|---|
| 标签族不匹配或超出支持范围 | 确认物理标签为 `tag36h11` 系列（系统默认配置 ID 为 $0 \sim 11$） |
| 图像曝光不足或过度曝光 | 通过服务调整曝光：`ros2 service call /{camera_id}/pylon_ros2_camera_node/set_exposure pylon_ros2_camera_interfaces/srv/SetExposure "{target_exposure: 15000.0}"` |
| 标签未在视野内或存在严重反光 | 调整相机对焦与补光角度，确保标签边缘对比度清晰 |
| 模块未在环境变量中启用 | 确认 [deploy/basler_camera/.env](deploy/basler_camera/.env) 中 `ENABLE_APRILTAG=true` |

## 3. 二维码识别异常或位姿话题缺失

### 症状表现
- 话题 `/{camera_id}/qr/decoded_info` 无文本输出。
- 话题 `/{camera_id}/qr/qr_pose` 未发布或提示内参无效。

### 排查步骤

```bash
# 1. 检查节点与组件加载状态
ros2 node list | grep wechat_qr_node

# 2. 检查模型加载日志与后端状态 (是否 fallback 到 OpenCV)
docker logs basler_camera --tail 100 | grep -E "WeChatQR|fallback to OpenCV"

# 3. 检查相机内参是否为占位参数 (fx, fy <= 1.0)
ros2 topic echo /{camera_id}/pylon_ros2_camera_node/camera_info --once | grep -A 4 "k:"
```

### 常见原因与解决方案
| 常见原因 | 解决方案 |
|---|---|
| 相机内参为占位值 ($f_x, f_y \le 1.0$) | `qr_pose` 依赖有效相机内参解算 `solvePnP`；需加载实际内参标定 YAML 文件 |
| WeChatQR 模型文件丢失 | 确认 [src/qrcode_detector/models/](src/qrcode_detector/models/) 存在 `.caffemodel` 与 `.prototxt` |
| 最小检测间隔门控 | 系统默认 `min_detect_interval_s=0.2`（最高约 5Hz），属于正常降频保护机制 |
| 相同内容去重抑制 | 系统默认 `deduplicate_window_s=0.5`，短时间内重复内容不会重复发布 |

## 4. Keyence 扫码器通信故障

### 症状表现
- 调用服务 `ros2 service call /{camera_id}/scanner/trigger std_srvs/srv/Trigger {}` 返回 `success=False`。
- 日志持续报错 `Failed to connect to scanner` 或连接超时。

### 排查步骤

```bash
# 1. 检查网络连通性
ping -c 3 172.31.0.91

# 2. 检查扫码器 TCP 端口连通性
nc -zv 172.31.0.91 9004

# 3. 手动通过 socket 发送 LON 扫码测试指令
echo -ne "LON\r" | nc 172.31.0.91 9004 -w 3

# 4. 检查节点诊断状态
ros2 topic echo /{camera_id}/diagnostics --once | grep -A 8 "Scanner Connection"
```

### 常见原因与解决方案
| 常见原因 | 解决方案 |
|---|---|
| 扫码器 IP 或端口配置错误 | 检查并在 [deploy/basler_camera/.env](deploy/basler_camera/.env) 中修正 `SCANNER_IP` 与 `SCANNER_PORT`（$1 \sim 65535$） |
| 设备未上电或网线松脱 | 检查扫码器供电与指示灯状态，确认工控机网口配置在同网段 |
| 防火墙拦截 TCP 端口 | 开放端口：`sudo ufw allow 9004/tcp` |

## 5. 状态聚合与健康检查异常 (`ERROR` / `STALE`)

### 症状表现
- 话题 `/{camera_id}/vision/status` 报告 `overall_level=2 (ERROR)`。
- Docker 容器被健康检查标记为 `unhealthy`。

### 排查步骤

```bash
# 1. 查看综合状态详细消息
ros2 topic echo /{camera_id}/vision/status --once

# 2. 手动运行容器健康检查探针
docker exec basler_camera /opt/ros2_ws/deploy/basler_camera/healthcheck.sh

# 3. 查看所有组件诊断原始数据
ros2 topic echo /{camera_id}/diagnostics --once
```

### 常见原因与解决方案
| 常见原因 | 解决方案 |
|---|---|
| 已启用模块的诊断超时 (>5s) 未更新 | 检查对应节点是否崩溃（如 `wechat_qr_node`、`apriltag_pose_reader`），确认其正常运行 |
| 相机 `camera_info` 消息断流 | 检查相机物理连接与网卡丢包，确认相机发布频率稳定 |
| 误将禁用的模块视作故障 | 在 [deploy/basler_camera/.env](deploy/basler_camera/.env) 中确认该模块是否已显式配置为 `true` |

## 6. 多相机流水线冲突

### 症状表现
- 两个相机的图像或检测数据相互覆盖。
- 第二路流水线未启动。

### 排查步骤

```bash
# 1. 查看启动日志确认两路流水线参数
docker logs basler_camera | grep -E "Pipeline|launching"

# 2. 检查话题命名空间是否严格隔离
ros2 topic list | grep -E "cam1|cam2"

# 3. 检查 TF 树中坐标系是否冲突
ros2 run tf2_tools view_frames
```

### 常见原因与解决方案
| 常见原因 | 解决方案 |
|---|---|
| 两路相机 ID 相同 | 必须保证 `CAMERA_ID` 与 `CAMERA_ID_2` 互不相同（例如 `cam1` 与 `cam2`） |
| 两路配置文件相同 | 必须分别指定独立的 YAML 配置文件（例如 `cam1.yaml` 与 `cam2.yaml`） |
| AprilTag 相机坐标系冲突 | 第二路必须指定独立的 `CAMERA_FRAME_2`，两路 AprilTag child frame 会自动加上前缀隔离 |

## 7. 常用快速诊断命令速查表

```bash
# 1. 检查节点拓扑
ros2 node list

# 2. 检查图像发布帧率
ros2 topic hz /{camera_id}/pylon_ros2_camera_node/image_raw

# 3. 监听关键算法输出
ros2 topic echo /{camera_id}/qr/decoded_info --once
ros2 topic echo /{camera_id}/qr/qr_pose --once
ros2 topic echo /{camera_id}/apriltag/pose --once
ros2 topic echo /{camera_id}/scanner/barcode --once

# 4. 检查综合状态与诊断
ros2 topic echo /{camera_id}/vision/status --once
ros2 topic echo /{camera_id}/diagnostics --once

# 5. 测试扫码器单次触发
ros2 service call /{camera_id}/scanner/trigger std_srvs/srv/Trigger {}

# 6. 容器健康检查
docker exec basler_camera /opt/ros2_ws/deploy/basler_camera/healthcheck.sh
```
