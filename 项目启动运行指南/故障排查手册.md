# 故障排查手册

本文档列出工业视觉系统常见故障及排查步骤。适用于统一容器部署模式。

---

## 1. 相机无法连接

### 症状
- healthcheck 失败：`camera_info` 话题无数据
- 日志出现 `Failed to connect to camera` 或 `No camera found`

### 排查步骤

```bash
# 1. 确认相机网络可达
ping 172.31.0.88

# 2. 检查 GigE 网口是否 UP
ip link show eth0

# 3. 确认 pylon SDK 能发现相机
/opt/pylon/bin/pylon_ip_auto_config

# 4. 检查相机序列号是否与配置匹配
grep serial_number src/pylon_ros2_camera_wrapper/config/aca2500_106611_18.yaml
```

### 常见原因
| 原因 | 解决 |
|------|------|
| 相机 IP 变更 | 运行 `pylon_ip_auto_config` 或重新配置相机 IP |
| MTU 不匹配 | 将 `mtu_size` 设为 1500（非 Jumbo Frame 网络） |
| 序列号不匹配 | 更新 YAML 配置中的 `serial_number` |
| 防火墙阻断 | `sudo ufw allow 3956-3992/udp`（GigE Vision 端口） |

## 2. AprilTag 检测不到标签

### 症状
- `/apriltag/pose` 话题无数据
- 日志中无 `AprilTag detection` 输出

### 排查步骤

```bash
# 1. 确认相机出图正常
ros2 topic hz /{camera_id}/pylon_ros2_camera_node/image_raw

# 2. 确认 apriltag_ros 节点在运行
ros2 node list | grep apriltag

# 3. 检查 detections 话题
ros2 topic echo /{camera_id}/detections --once

# 4. 确认标签族和尺寸配置
cat src/apriltag_pose_reader/config/apriltag_36h11.yaml
```

### 常见原因
| 原因 | 解决 |
|------|------|
| 标签不在视野内 | 调整相机角度/距离 |
| 曝光不当 | 调整 `exposure` 参数，避免过曝/欠曝 |
| 标签尺寸配置错误 | 更新 `apriltag_36h11.yaml` 中的 `size` 字段（单位：米） |
| 标签族不匹配 | 确认物理标签是 `36h11` 族，与配置一致 |
| `enable_apriltag=false` | 检查 launch 参数或 `.env` 中的 `ENABLE_APRILTAG` |

## 3. 二维码无法识别

### 症状
- `/qr/decoded_info` 话题无数据
- 日志无 `✅ 识别到二维码` 输出

### 排查步骤

```bash
# 1. 确认压缩图像流正常
ros2 topic hz /{camera_id}/pylon_ros2_camera_node/image_raw/compressed

# 2. 检查 QR 节点是否降级为 OpenCV 后端
ros2 launch 日志中查找 "fallback to QRCodeDetector"

# 3. 确认模型文件存在
ls install/qrcode_detector/share/qrcode_detector/models/
```

### 常见原因
| 原因 | 解决 |
|------|------|
| WeChatQR 模型缺失 | 运行 `python3 src/qrcode_detector/scripts/download_models.py` |
| OpenCV 无 wechat_qrcode 模块 | 安装 `opencv-contrib-python-headless` |
| 二维码太小/模糊 | 降低 binning 或靠近二维码 |
| 检测帧率门控 | 调小 `min_detect_interval_s`（默认 0.2s = 最高 5Hz） |
| 去重窗口过滤 | 调小 `deduplicate_window_s` 或设为 0 禁用 |

## 4. Keyence 扫码器通信失败

### 症状
- 调用 `/scanner/trigger` 服务返回 `success=False`
- 日志出现 `Failed to connect to scanner` 或 `Timeout`

### 排查步骤

```bash
# 1. 确认扫码器网络可达
ping 172.31.0.91

# 2. 测试 TCP 端口连通性
nc -zv 172.31.0.91 9004

# 3. 检查节点诊断信息
ros2 topic echo /diagnostics --once | grep -A5 "Scanner Connection"

# 4. 手动发送测试命令
echo -ne "LON\r" | nc 172.31.0.91 9004 -w 3
```

### 常见原因
| 原因 | 解决 |
|------|------|
| 扫码器 IP/端口错误 | 更新 `.env` 中的 `SCANNER_IP`/`SCANNER_PORT` |
| 扫码器忙/离线 | 等待重连（默认 5s 间隔），或检查扫码器电源 |
| 协议不匹配 | 确认扫码器设置为 SR-1000 ASCII 协议模式 |
| 防火墙阻断 | `sudo ufw allow 9004/tcp` |

## 5. 位姿估计不准确（QR / AprilTag）

### 症状
- 输出的 xyz 坐标偏差大
- 姿态四元数不稳定/跳变

### 排查步骤

```bash
# 1. 检查标定文件是否为占位值
grep "fx" src/pylon_ros2_camera_wrapper/config/aca2500_106611_18.calib.yaml
# 如果 fx ≈ 1.0，说明标定未执行

# 2. 使用 AprilGrid 重新标定
ros2 run apriltag_pose_reader apriltag_pipeline \
	/path/to/aprilgrid_images \
	--output-dir calibration_output
```

### 常见原因
| 原因 | 解决 |
|------|------|
| 标定文件是占位值 | 使用 4x3、tag36h11 AprilGrid 采集 15+ 张有效图像并重新生成 CameraInfo |
| QR 物理尺寸配置错误 | 更新 `qr_size_m` 参数（单位：米） |
| 相机振动 | 加固相机支架，或增加 `tag_timeout_s` 平滑 |

## 6. Docker 容器启动失败

### 症状
- `docker compose up` 后容器反复重启
- `docker ps` 显示容器状态为 `unhealthy`

### 排查步骤

```bash
# 1. 查看容器日志
docker logs basler_camera --tail 50

# 2. 手动执行 healthcheck
docker exec basler_camera /opt/ros2_ws/deploy/basler_camera/healthcheck.sh

# 3. 检查 pylon SDK 是否正确安装
docker exec basler_camera ls /opt/pylon/lib/

# 4. 检查 ROS2 工作区是否正确构建
docker exec basler_camera ls /opt/ros2_ws/install/
```

### 常见原因
| 原因 | 解决 |
|------|------|
| pylon SDK 未挂载 | 确认 `deploy/basler_camera/pylon-sdk/` 下有 `.tar.gz` 或 `.deb` 文件 |
| 镜像版本不匹配 | 重新 `docker build` 并更新 `.env` 中的 `BASLER_IMAGE` |
| start_period 不够 | 增大 `healthcheck.start_period`（相机初始化可能需要 30s+） |

## 7. 多相机话题冲突

### 症状
- 两个 pipeline 的输出话题互相覆盖
- 下游节点收到混乱的数据

### 排查步骤

```bash
# 1. 确认两个 pipeline 使用不同 camera_id
docker logs basler_camera 2>&1 | grep "Launching"

# 2. 列出所有话题，检查命名空间隔离
ros2 topic list | grep -E "cam1|cam2"

# 3. 确认下游节点订阅了正确的话题
ros2 node info /your_downstream_node
```

### 常见原因
| 原因 | 解决 |
|------|------|
| camera_id 相同 | 确保 `CAMERA_ID` 和 `CAMERA_ID_2` 不同 |
| 下游节点用了绝对话题名 | 改为 `/{camera_id}/...` 格式 |

## 快速诊断命令速查

```bash
# 节点列表
ros2 node list

# 话题频率
ros2 topic hz /{camera_id}/pylon_ros2_camera_node/image_raw

# 单次查看输出
ros2 topic echo /{camera_id}/qr/decoded_info --once
ros2 topic echo /{camera_id}/apriltag/pose --once
ros2 topic echo /{camera_id}/scanner/barcode --once

# 诊断信息
ros2 topic echo /diagnostics --once

# 服务调用测试
ros2 service call /{camera_id}/scanner/trigger std_srvs/srv/Trigger

# 参数查看
ros2 param get /{camera_id}/pylon_ros2_camera_node startup_user_set
ros2 param get /wechat_qr_node min_detect_interval_s

# 容器状态
docker ps
docker logs basler_camera --tail 20
docker exec basler_camera /opt/ros2_ws/deploy/basler_camera/healthcheck.sh
```

## 8. 诊断信息排查

### 查看节点诊断状态

```bash
# 查看所有诊断信息
ros2 topic echo /diagnostics --once

# 只看 Keyence 扫码器状态
ros2 topic echo /diagnostics --once | grep -A10 "Scanner Connection"

# 只看 AprilTag 状态
ros2 topic echo /diagnostics --once | grep -A10 "AprilTag Status"
```

### 诊断字段说明

| 字段 | 来源 | 正常值 | 异常含义 |
|------|------|--------|----------|
| `Scanner Connection` | Keyence | `Connected to IP:PORT` | `Disconnected` = 扫码器断连 |
| `scan_count` | Keyence | 递增 | 不增长 = 未触发扫码 |
| `error_count` | Keyence | 0 | 非零 = 通信错误累积 |
| `AprilTag Status` | AprilTag | `Detecting tags` | `No detections yet` = 未检测到标签 |
| `detections_seen` | AprilTag | 递增 | 不增长 = 检测节点异常 |
| `transforms_published` | AprilTag | 递增 | 不增长 = TF 链路断裂 |

## 10. QoS 兼容性排查

### 症状
- 订阅者收不到图像数据
- `ros2 topic echo` 无输出

### 排查步骤

```bash
# 1. 检查话题的 QoS 配置
ros2 topic info /{camera_id}/pylon_ros2_camera_node/image_raw -v

# 2. 检查订阅者的 QoS 配置
ros2 node info /{camera_id}/wechat_qr_node

# 3. 确认 QoS 兼容（发布者和订阅者必须匹配）
# BEST_EFFORT 发布者 → BEST_EFFORT 订阅者 ✅
# BEST_EFFORT 发布者 → RELIABLE 订阅者 ❌（FastDDS 下可能不兼容）
```

### 常见原因
| 原因 | 解决 |
|------|------|
| 第三方节点用 RELIABLE 订阅图像 | 改为 BEST_EFFORT 或使用 `rmw_qos_profile_t` 覆盖 |
| `depth` 不匹配 | 图像话题统一使用 `depth=1` |
