# 项目启动运行说明

适用范围：日常启动 Basler 相机、二维码识别和 AprilTag 检测。三个节点由同一个 `basler_camera` Docker 容器统一运行。

详细集成与调用文档（推荐先看）：
- `./工控机ROS2集成与调用超详细指南.md`

## 1. 启动前检查

确认相机已上电、网线已连接，并进入工作区：

```bash
cd /home/ubuntu/ros2_ws
```

首次部署或容器不存在时，先执行一次：

```bash
cp deploy/basler_camera/.env.example deploy/basler_camera/.env
docker compose --env-file deploy/basler_camera/.env \
  -f deploy/basler_camera/docker-compose.yml up -d
```

## 2. 日常启动

```bash
sudo -n docker restart basler_camera
sudo -n docker inspect --format '{{.State.Status}} {{.State.Health.Status}}' basler_camera
```

第二条命令应最终显示：

```text
running healthy
```

若刚重启仍显示 `starting`，等待约 30 秒后重复执行第二条命令。

## 3. 确认相机图像正常

```bash
sudo -n docker exec basler_camera bash -lc \
  'source /opt/ros/humble/setup.bash && source /opt/ros2_ws/install/setup.bash && \
   timeout 8 ros2 topic hz /my_camera/pylon_ros2_camera_node/image_raw'
```

能显示图像话题频率，即相机图像链路正常。

## 4. Keyence SR 扫码器

Keyence SR 节点由 `basler_camera` 容器随项目一起启动，默认连接扫码器 `172.31.0.91:9004`，无需在宿主机单独启动节点。

先在一个终端持续监听扫码结果：

```bash
sudo -n docker exec basler_camera bash -lc \
  'source /opt/ros/humble/setup.bash && source /opt/ros2_ws/install/setup.bash && \
   ros2 topic echo /my_camera/scanner/barcode'
```

在另一个终端触发一次扫码：

```bash
sudo -n docker exec basler_camera bash -lc \
  'source /opt/ros/humble/setup.bash && source /opt/ros2_ws/install/setup.bash && \
   ros2 service call /my_camera/scanner/trigger std_srvs/srv/Trigger {}'
```

服务返回 `success: true` 且 `/my_camera/scanner/barcode` 输出字符串，即扫码正常。

如需更换扫码器地址，修改下列命令中的 IP、端口和重连间隔后执行；容器会按新参数重建：

```bash
cd /home/ubuntu/ros2_ws
SCANNER_IP=172.31.0.92 SCANNER_PORT=9004 RECONNECT_INTERVAL_S=3.0 \
sudo -n docker compose -f deploy/basler_camera/docker-compose.yml \
  up -d --force-recreate
```

## 7. 相机标定（AprilTag AprilGrid，完整流程）

### 7.1 标定目标

本项目采用 AprilTag 标定板（AprilGrid）进行相机内参和外参标定，标定板要求如下：

- 类型：AprilTag 标定板（AprilGrid）
- 布局：4 行 × 3 列，共 12 个 Tag
- Tag 边长：50mm
- Tag 间距：10mm（相邻两个 Tag 黑色边框之间的白色间隙）
- 家族/版本：tag36h11

项目中已在代码中加入对应规格约束，并提供了完整的采集、检测和标定脚本：

- `src/apriltag_pose_reader/apriltag_pose_reader/aprilgrid_spec.py`
- `src/apriltag_pose_reader/apriltag_pose_reader/aprilgrid_capture.py`
- `src/apriltag_pose_reader/apriltag_pose_reader/aprilgrid_calibration.py`
- `src/apriltag_pose_reader/apriltag_pose_reader/aprilgrid_pipeline.py`

### 7.2 标定原理说明

相机标定的核心思想是：

1. 让相机拍摄已知尺寸的 AprilGrid 标定板；
2. 使用 AprilTag 检测算法识别每个 Tag 的角点像素坐标；
3. 结合已知的 3D 物理坐标（Tag 真实世界尺寸、布局参数）与 2D 像素坐标，建立对应关系；
4. 通过 OpenCV 的 `calibrateCamera` 估计相机内参矩阵 `K` 和畸变参数 `D`；
5. 对每一帧图像进一步估计标定板在相机坐标系中的位姿（外参 `R`, `t`）；
6. 最终生成 ROS 所需的 CameraInfo YAML 文件。

对于此项目，Tag 之间不是裸粵式简单编号，而是按照 4×3 的网格排列，物理坐标按如下规则布置：

- 每个 Tag 边长为 0.05m（50mm）
- 每两个相邻 Tag 的中心距离为 `0.05 + 0.01 = 0.06m`
- 因此整个板的几何尺寸可用该网格模型精确描述

### 7.3 标定前准备

#### 1）先确认环境

```bash
cd /home/ubuntu/ros2_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
```

如果还未编译当前 ROS 包，先执行：

```bash
cd /home/ubuntu/ros2_ws
source /opt/ros/humble/setup.bash
colcon build --packages-select apriltag_pose_reader
source install/setup.bash
```

#### 2）确认工作区中有标定脚本

```bash
ros2 run apriltag_pose_reader apriltag_calibration --help
ros2 run apriltag_pose_reader apriltag_capture --help
ros2 run apriltag_pose_reader apriltag_pipeline --help
```

若命令输出帮助信息，则说明当前环境可以使用标定脚本。

### 7.4 标定板准备

在正式标定前，请准备：

- 一张 4 行 × 3 列的 AprilGrid 标定板
- 标签族为 `tag36h11`
- 每个 Tag 边长 50mm，且两 Tag 之间保留 10mm 间隔
- 打印时确保白边、黑边、打印精度均匀，不要严重变形

建议：

- 标定板用 A4 或更大尺寸纸张打印，避免边缘裁切干扰
- 标定板需要尽量贴平并保持无明显弯曲
- 相机镜头与标定板尽量保持稳定，不要在标定过程中手持移动相机

### 7.5 采集标定图像（推荐方式）

#### 方案 A：从 ROS2 图像保存标定图片

先确认相机已启动成功：

```bash
sudo -n docker exec basler_camera bash -lc \
  'source /opt/ros/humble/setup.bash && source /opt/ros2_ws/install/setup.bash && \
   timeout 8 ros2 topic hz /my_camera/pylon_ros2_camera_node/image_raw'
```

确认图像话题正常后，使用项目现有 ROS2 图像保存工具或现场采集程序保存图片。AprilGrid 标定程序不直接打开 Linux 摄像头设备读取 Basler 相机。

```bash
cd /home/ubuntu/ros2_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 run apriltag_pose_reader apriltag_capture \
  --input-dir /path/to/aprilgrid_images \
  --output-dir calibration_images \
  --prefix calib
```

说明：

- `--input-dir` 是已经从 ROS2 图像话题保存的图片目录
- `--output-dir` 是标定流水线使用的图片目录
- 实际使用时建议至少 15~25 张有效图，且图像要覆盖不同角度、不同位置和不同姿态
- 标定板固定：可将标定板牢固粘贴在平整墙面或刚性支架上，确保其平面度与尺寸稳定性。此时只需控制相机在多个角度（俯仰、偏航、滚动）、不同距离（近、中、远）和不同位置（左上、右下、中心等）进行拍摄，即可覆盖充分的视角变化。

#### 方案 B：从已有图片目录批量校准

如果你已经有一批标定图文件，可以直接整理到某个目录后执行：

```bash
cd /home/ubuntu/ros2_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 run apriltag_pose_reader apriltag_capture --input-dir /path/to/image_dir --output-dir calibration_images
```

### 7.6 标定图像采集要求

优秀的标定图片应满足：

- 目标板覆盖约 30%~80% 的图像视野
- 标定板朝向不同角度：正视、侧视、倾斜、旋转
- 持续采集多张图，不要只拍一张或极少几张
- 每张图中至少能看到多个 Tag，理想是 4～12 个 Tag 均可检测
- 图像尽量避免过曝、过暗、强反光和严重模糊

建议至少采集：

```text
15 ~ 30 张有效图像
```

### 7.7 执行完整标定流程

采集完成后，直接运行完整标定流水线：

```bash
cd /home/ubuntu/ros2_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 run apriltag_pose_reader apriltag_pipeline calibration_images --output-dir calibration_output
```

该命令会自动执行：

1. 读取 `calibration_images` 中的图像
2. 识别 AprilTag 的角点
3. 使用网格几何参数构造 3D 点云
4. 调用 OpenCV `calibrateCamera` 估算内参
5. 计算每张图对应的 board 外参
6. 输出 YAML 文件：`calibration_output/camera_calibration.yaml`

### 7.8 直接执行单步校准（可选）

如果你只想直接从图像列表转换成内参 YAML，可使用：

```bash
cd /home/ubuntu/ros2_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
PYTHONPATH=/home/ubuntu/ros2_ws/src/apriltag_pose_reader python3 \
  src/apriltag_pose_reader/apriltag_pose_reader/aprilgrid_calibration.py \
  calibration_images/calib_000.png calibration_images/calib_001.png calibration_images/calib_002.png \
  --output calibration_output/camera_calibration.yaml
```

注意：

- 最少需要 3 张有效图像
- 实际使用时建议 10+ 张图像以提高稳定性
- 图像须包含清晰可检测的 tag36h11 标签

### 7.9 输出结果说明

生成的 YAML 主要包括：

- `camera_name`
- `image_width`
- `image_height`
- `camera_matrix`
- `distortion_model`
- `distortion_coefficients`
- `rectification_matrix`
- `projection_matrix`

这是 ROS / `camera_info_manager` 能直接使用的标准 CameraInfo 格式。

### 7.10 将标定结果应用到项目相机配置

当前项目相机配置文件在：

- `src/pylon_ros2_camera_wrapper/config/aca2500_106611_18.calib.yaml`

使用方法：

1. 将新生成的 `camera_calibration.yaml` 中的内参覆盖到该文件；
2. 或将其复制为同目录下的 `*.calib.yaml` 文件；
3. 保证 `camera_info_url` 指向正确的 YAML 文件；
4. 重启相机容器或重启视觉节点以加载新参数。

示例：

```bash
cd /home/ubuntu/ros2_ws
cp calibration_output/camera_calibration.yaml \
  src/pylon_ros2_camera_wrapper/config/aca2500_106611_18.calib.yaml
```

随后重启相机容器：

```bash

```

### 7.11 标定完成后的验证

标定完成以后，建议执行以下验证：

```bash
sudo -n docker exec basler_camera bash -lc \
  'source /opt/ros/humble/setup.bash && source /opt/ros2_ws/install/setup.bash && \
   ros2 topic echo /my_camera/apriltag/pose --once'
```

若能稳定输出 Tag 位姿，并且相机图像畸变明显减小，则说明：

- 内参标定有效；
- AprilTag 检测链路正常；
- 相机参数已应用成功。

### 7.12 常见问题排查

#### 1）检测不到 Tag

检查：

- `tag36h11` 是否与实际板一致
- 标定板是否打印清晰、边缘无变形
- 图像是否过暗、过曝、聚焦不清
- 相机是否已处于正确分辨率和曝光状态

#### 2）标定失败 / `Need at least 3 calibration images`

原因：

- 采集图像较少
- 图像中没有足够多个可识别 Tag
- 图像存在严重模糊或过曝

解决：

- 增加有效图像数量
- 增大目标板在图中的占比
- 增加不同视角和不同角度的图像

#### 3）输出的内参数值看起来异常

检查：

- 是否为错误打印尺寸（例如分辨率不对）
- 是否为错误的 `camera_info_url` 指向
- 标定板几何参数是否与实际板一致

## 8. 机械臂末端相机手眼标定

当前相机刚性固定在机械臂末端法兰，属于 `eye_in_hand`。AprilGrid 标定板应固定在工作台或机器人基座参考系，标定板在采集过程中不得移动。

### 8.1 标定顺序

内参标定和手眼标定可以分开执行，推荐顺序如下：

1. 使用本章前面的 AprilGrid 流程完成内参标定，得到有效的 `camera_matrix` 和 `distortion_coefficients`。
2. 让机械臂带着相机移动到 10～20 个不同位置和姿态。
3. 每个姿态下同步记录机器人末端位姿和 AprilGrid 在相机中的位姿。
4. 使用 `scripts/handeye_calibrate.py` 离线求解固定的相机安装变换。
5. 先在低速、低风险位置进行实机验证，再用于抓取或定位。

### 8.2 安装并检查 xArm 7 驱动

安装官方 `xarm_ros2` 后，使用与 ROS2 Humble 匹配的工作区启动 xArm 7 驱动。将 IP 替换为实际控制器地址：

```bash
source /opt/ros/humble/setup.bash
source ~/xarm_ros2/install/setup.bash
ros2 launch xarm_api xarm7_driver.launch.py robot_ip:=192.168.1.XXX
```

确认机器人状态话题和消息内容：

```bash
ros2 topic list -t | grep robot_states
ros2 topic echo /xarm/robot_states --once
```

默认话题为 `/xarm/robot_states`。如果实际命名空间不是 `/xarm`，以 `ros2 topic list -t` 的结果为准，并在采集命令中修改 `--robot-states-topic`。`RobotMsg.pose` 的格式为 `[x, y, z, roll, pitch, yaw]`，其中前三项是毫米，后三项是弧度。

### 8.3 xArm 7 自动采集手眼数据

先启动相机和 AprilTag 检测链路，确认目标标签 TF 正常：

```bash
ros2 topic echo /apriltag/transform --once
```

然后启动自动采集节点：

```bash
cd /home/ubuntu/ros2_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 run apriltag_pose_reader xarm_handeye_capture \
  --robot-states-topic /xarm/robot_states \
  --tag-transform-topic /apriltag/transform \
  --target-frame tag36h11:3 \
  --output-dir handeye_dataset \
  --samples 15 \
  --sync-tolerance-s 0.10
```

程序默认只采集，不控制机械臂移动。操作员每次手动将 xArm 7 移动到一个新姿态，停稳后等待程序输出 `Collected N/15 synchronized samples`。采集节点会：

- 从 `/xarm/robot_states` 读取末端位姿；
- 将 xArm 毫米单位转换为米；
- 将末端滚转、俯仰、偏航转换为旋转矩阵；
- 从 `/apriltag/transform` 读取 `camera -> tag` 变换；
- 按时间戳配对两类数据；
- 过滤时间不同步、运动不足和重复样本；
- 输出 `handeye_dataset/poses.csv`。

建议采集 15～20 个样本，覆盖不同位置、距离和姿态。采集结束按 `Ctrl-C` 也会写出当前 CSV。节点不会调用 xArm 的运动服务；在没有确认工作空间、TCP 配置、速度限制和急停方案之前，不要添加自动运动控制。

### 8.4 CSV 数据格式

CSV 首行必须包含以下字段：

```text
gripper2base_r,gripper2base_t,target2cam_r,target2cam_t
1 0 0 0 1 0 0 0 1,0.1 0.2 0.3,1 0 0 0 1 0 0 0 1,0.02 0.01 0.5
```

每一行是一个同步样本：

- `gripper2base_r/t`：机械臂末端在基座坐标系中的姿态。
- `target2cam_r/t`：AprilGrid 标定板在相机坐标系中的姿态。
- 平移单位必须是米；旋转矩阵按行展开为 9 个数。
- 如果控制器导出的是 `base2gripper`，必须先求逆再写入 `gripper2base`。
- 采样时应改变位置、俯仰、偏航和滚转，不能只做平移或只使用近似相同的姿态。

### 8.5 执行手眼标定

在工作区执行：

```bash
cd /home/ubuntu/ros2_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
python3 scripts/handeye_calibrate.py \
  --input poses.csv \
  --output calibration_output/handeye.yaml \
  --algorithm park \
  --base-frame base_link \
  --gripper-frame tool0 \
  --camera-frame camera_optical_frame \
  --target-frame apriltag_board
```

程序会检查旋转矩阵、样本数量和姿态变化，并输出：

- `camera_to_gripper_rotation`
- `camera_to_gripper_translation_m`
- `camera_to_gripper_matrix`
- `gripper_to_camera_matrix`
- 样本数量、算法和闭环误差统计

这里的核心结果是固定安装变换：

$$
{}^{gripper}T_{camera}
$$

运行时应与机器人动态 TF 组合：

$$
{}^{base}T_{camera} = {}^{base}T_{gripper} \cdot {}^{gripper}T_{camera}
$$

因此，不能把手眼输出文件直接当作静态 `base_link -> camera` 变换。机器人驱动提供 `base_link -> tool0`，手眼结果提供 `tool0 -> camera_optical_frame`，两者组合后才是当前相机在基座中的实时姿态。

### 8.6 结果验证

先检查结果文件中的闭环误差，再进行现场验证：

1. 让机器人低速移动到一个未参与标定的姿态。
2. 读取 AprilTag 位姿并转换到 `base_link`。
3. 机器人移动到该预测位置附近，确认误差方向和量级正确。
4. 使用不同距离、不同姿态重复验证至少 3 次。
5. 一旦出现轴方向反、单位错误或姿态跳变，立即停止运动，优先检查变换方向和机器人控制器导出格式。

当前程序使用离线 CSV，不绑定具体机械臂品牌。后续如需自动采集，可在确认机器人 TF 命名和同步机制后增加 ROS2 采集节点。

## 9. 停止项目

```bash
sudo -n docker stop basler_camera
```

## 注意事项

- 日常运行只管理 `basler_camera` 容器；不要在宿主机另行启动 `pylon_ros2_camera_wrapper`，否则可能抢占相机。
- Keyence SR 无法扫码时，先确认扫码器已上电且主机网络可访问其配置的 IP 与端口。
- Docker 命令中的 `sudo -n` 需要当前用户具备免密 sudo；若命令提示权限不足，请使用有权限的账户执行。
